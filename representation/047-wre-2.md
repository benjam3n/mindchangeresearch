# Original-position edit requirements

Actual starting judgment: “Delete the first item, then tag the second” looked executable from the visible list. I had not fixed whether “second” bound before or after deletion.

Concrete input: Initial list `[A:alpha, B:beta, C:gamma]`. Delete original A and tag original B. The same instruction must preserve those targets after the list is reordered to `[C,A,B]`; duplicate or missing IDs must fail before mutation.

Actor and scope: This model derives and checks an edit instruction against stipulated records. No human editor’s speed, comprehension or accuracy is observed.

Source: original `wre`, interpretation 1, SHA-256 `f3b5104ed229787c7fec425cca9e2928b26767cf1e0b03cf0ef05aa2b838741e`. [The ARAW dependency](finish-wre-edit-araw.md) remains partial on semantic recursion; [the AEX dependency](finish-wre-edit-aex.md) satisfies its 8× assumption floors.

## Stage 0 — artifact definition

Type: revision instruction. Venue: a versioned document-edit request. Reader: an editor/system that can inspect stable IDs and perform delete/tag operations. Baseline: understands lists and record IDs; does not know whether ordinals are live or original. Goal: preserve intended target identities and atomic failure. After-state: A absent, B tagged, C unchanged. Core question: How must targets be bound before deletion changes positions? Scope: this three-record revision and reorder; not a universal transaction system. Stakes: live ordinal resolution tags C instead of B.

## Stage 1 — thesis object

Core thesis: For this original-snapshot request, resolve A and B to unique live IDs before mutation, then delete A and tag B atomically; the result is B tagged and C unchanged in both declared orders.

Claim type: normative/technical. Weaker claim: destructive edits need care. Stronger refused: all edits must use stable IDs and be atomic; refused because a deliberately live-position operation can correctly target the list after each mutation. Actual claim: stable pre-resolved identities are required when the nouns refer to original items and failure must preserve the input.

Supporting claims: C1 live positions change after deletion; C2 unique IDs preserve identity across reorder; C3 preflight distinguishes atomic failure from partial failure. Out of scope: O1 IDs prove content has not changed. O2 final-state equality proves no forbidden intermediate operation occurred. O3 name-based prose improves human accuracy.

L1 Binding — depends on none; satisfies E1,E2; exit: original A/B denote stable IDs in one version. L2 Preflight — depends on L1; satisfies E3,E4; exit: exactly one live A and B or no mutation. L3 Apply — depends on L2; satisfies E5; exit: A absent, B tagged, C unchanged. L4 Boundary tests — depends on L3; satisfies E6,E7; exit: live-ordinal and reorder behavior differ for stated reasons.

## Stage 7 — traceability and sensitivity

Coverage: T1 applies across L1–L4; T2/T3→E1/E2→L1; T4–T6→E3/E4→L2; T7/T8→E5→L3; T9–T13→E6/E7→L4. P1/P2/P7→E1/E2→L1; P3/P6/P10→E3/E4→L2; P5/P12→E5→L3; P4/P8/P9/P11/P13→E6/E7→L4. Unsatisfied requirements: zero. Decorative E/L elements: zero.

Sensitivity: live positions on `[A,B,C]` produce `[B,C(tagged)]`; original identities produce `[B(tagged),C]`. Reorder to `[C,A,B]` and the ID request still removes A/tags B, yielding `[C,B(tagged)]`. Duplicate B yields two matches and must abort. Swap the two disjoint ID operations and the same final state results; swap their positional analogues and it does not. Remove the preflight and a missing B can leave A already deleted.

Adversarial review: “Stable ID” alone fails on `[A,B,B]`, so uniqueness is promoted to a gate. Binding IDs alone also fails if the old task is applied to a new version with different requested targets, so a version/task precondition is included. These additions are not evidence that all edits need transactions.
