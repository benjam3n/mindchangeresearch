# Ordering an evidence record for inspection

Starting working state: The archive naturally makes source-first reading attractive: skill source, comparison, application, finding, boundary, next attempt. That remains a strong order for checking source fidelity. The immediate reviewer task is deciding reuse, not learning the method.

Input and execution scope: This is application 1 of `ro` in the representation line. The actor whose working state is observed is this model in this local research run. Human effects are untested unless explicitly identified otherwise.

Source: [original ro](../sources/representation-ro.md); [separate requirements](../sources/representation-ro.requirements.txt). Emitted source SHA-256 `62b10d5bd32f960bf5a2493e4ec7c3321b7b37444848b442b56e7b2c88548845`. The complete receipt is in [source-receipts.json](source-receipts.json).

Depth accounting: Original 8x floor met: six independent-purpose dimensions, every item scored, all 15 pairs compared, every placement checked, three materially different orders, full confidence map, and three weight shifts. The numeric weights are disclosed judgment inputs, not empirical data.

Original list: S source, C comparison, A application, F finding, B boundary, N next attempt. N=6. Objective: expose what bears on a reuse decision early while retaining audit access. Type: inspection priority, not the authoring execution sequence. The first intent sentence is fixed outside this list. The scope-bearing finding must never be presented as unqualified proof.

Six dimensions, five-point scale; weights are explicit local preferences, not measured utilities. U decision usefulness (high=3); E direct effect evidence (high=3); D independence from earlier sections (medium=2); L limitation visibility (high=3); P provenance access (medium=2); R future action discrimination (medium=2). These separate functions: a source has excellent provenance but supplies no local effect, and a boundary has excellent limitation visibility but need not contain provenance.

The 15 complete pair comparisons use the total only as a preference guide. F>A by one: finding names the proposition whose evidence A supplies. F>B: a boundary needs a finding to bound. F>C: comparison needs the live question. F>S: local reuse differs from byte fidelity. F>N: completed result before unperformed future work. A>B: effect first permits the reader to understand what the boundary limits, but the scoped finding carries the key limitation immediately. A>C: actual result outranks predicted comparison. A>S: source alone cannot show effect. A>N: performed action before proposals. B>C: the veto condition is needed before importing comparative advantages. B>S: scope can disqualify even a faithful execution. B>N: present exclusion before future inquiry. C>S: contested causal/use comparison before detailed source audit. C>N: the existing alternatives establish what the next attempt must improve. N>S by raw score, but S is placed before N because the next attempt depends on understanding the retained source basis; this is a declared dependency override, not a secret score change.

Reordered: F (62), A (61), B (60), C (51), S (36), N (41). Movements: S 1→5, C 2→4, A 3→2, F 4→1, B 5→3, N stays 6. Confidence high on F before N and A before N; medium on B before C; low on F/A and A/B, which can move two positions when the reviewer has already read the finding. Most debatable: B; a known-result reviewer needs B first.

Complete sanity review: the top three all bear directly on whether reuse is justified; the bottom group supplies comparisons, audit detail, and future work, none dispensable. F/A/B near ties are resolved by proposition→evidence→scope, with the scope also attached to F so early stopping does not lose it. S/N is dependency-corrected. No authoring dependency is reversed: sources are still read before execution, even when displayed fifth.

Alternative orderings: source-audit task S,C,A,F,B,N; applicability task B,F,A,C,S,N; current general inspection F,A,B,C,S,N. Weight sensitivity: raising P from 2 to 5 moves S above N numerically and narrows its gap to C, but does not beat F/A because source bytes do not supply effect. Raising L to 6 makes B the first item (75 versus F71/A70), which is defensible for a transfer reviewer. Setting E to 1 lowers A relative to B and F, revealing that this order assumes effect evidence matters. These calculations are rankings of declared judgments; no claim of objective optimality follows.

Actual use: the next organization question, “Does local source storage qualify as durable program memory?”, was inspected in F,A,B,C,S,N order. F: no durability claim from scratch existence. A: exact files exist locally. B: root owns persistent saving. C: local receipt versus saved deliverable. S: supplied authority instruction. N: root handoff. The resulting disposition is a root saving dependency rather than a local claim of persistent memory. The source-first alternative reaches the same correct disposition; the changed order makes the claim and exclusion adjacent without measuring elapsed time.

Certificate: claim—F,A,B,C,S,N is the chosen general inspection order under the stated local dimensions and dependency. The full pair set and sensitivity show both the reason for it and the conditions that reverse it. Strong contrary—source-first is superior for archive-fidelity auditing; retained as a named alternate, so the general order is not universal. Unresolved—actual reviewer speed and preference. KEEP concerns the task-conditioned selection and use, not a fabricated speed gain.

Actual mind change: I now distinguish authoring order from inspection order and used a reuse-oriented record order on the durability question. The strongest alternate order is retained for source audits.

Benefit: The local reviewer representation makes the claim, its observed effect, and its disqualifying boundary adjacent; the performed durability disposition remained correctly limited. This is structural access evidence, not a human timing experiment.

Verdict: KEEP — task-conditioned inspection ordering.

Organization: Finding→application→boundary→comparison→source→next is the default review route; source-audit and applicability routes remain explicit alternatives.

Next attempts: Test a known finding with a novel actor; give a source auditor the alternate route; replace any score dimension that proves nondiscriminating on later inputs.
