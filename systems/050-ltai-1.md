# Make a handoff resistant to a late obsolete result

Starting judgment: A returned result with a matching task name appears relevant. The baseline contract I would use carries a task label and output; it does not yet encode the version of the requested target.

Actor and scope: The assistant's current working representation and operations in this systems line. This record does not establish human effects, model-weight changes, or transfer to another session.

Source: `../sources/systems-ltai.md`; current requirements are retained separately in `../sources/systems-ltai.requirements.txt`.

Depth: The original defines no numerical 8x floor. The expanded execution below covers the actual operations and multiple dependencies/countercases; no numerical 8x certification is asserted.

Input: a constructed coordinator has target T revision 1. Work starts for revision 1; the user changes T to revision 2; the old work returns. No real agent is spawned. The coordination transition is executed locally.

Suitability map: mechanically comparing target revision and output identity is fully automatable; interpreting whether a semantic target changed is agent-assisted; deciding the user's values is human-led; impersonating the user's approval is prohibited. Novel reasoning outputs remain reviewable rather than presumed correct.

Handoff: trigger is dispatch of T; input is task, revision, payload; processing verifies task and revision, then records status; output is accepted/rejected plus reason; endpoint is coordinator state; quality gate requires exact current revision and a nonempty output. A stale result is retained as historical evidence, not silently promoted.

Recovery: wrong revision → reject and request a current result once; missing revision → reject contract and return to producer; duplicate accepted result → keep one identity; absent output → reject. Retry cap is one per revision; further failure returns to root as the current coordinator. Rollback restores the previous accepted result and never claims it answers the new revision. User/root stop remains the oversight authority.

Oversight record: current target revision, last accepted output, rejected returns and pending work. Review occurs on every result. A stop flag is checked before accepting another result; the simulation can halt immediately between transitions. It does not claim interruption inside unavailable external tools.

Capability evolution: at 0–6, 6–18 and 18+ months, this plan makes no model capability prediction. Transition to unattended handling would require observed contract reliability in the then-available runtime; unfamiliar semantic tasks remain reviewed until evidence changes. Prepared now: a versioned contract and a retained rejection reason. No automatic future task has been scheduled.

Actual execution in `handoff-version-test.json`: label-only baseline accepts revision-1 output for current revision 2. The revised contract rejects that output, accepts revision 2, rejects missing revision, and prevents duplicate acceptance. The earlier behavior and repair are both retained. The trace verifies four concrete transition cases, not general autonomous reliability.

Actual mind change: The coordinator now accepts a returned result only for its current target revision; obsolete results remain historical.

Benefit: The locally executed stale-return case changes from incorrect acceptance to explicit rejection, with a current revision still accepted. No claim about a production agent population follows.

Verdict: KEEP

Organization: The transition trace makes event order visible; a prose handoff without target revision omits the decisive relation.
