# Working memory

Candidate contributors describe possible functional relationships. Each source marker supports only its attached statement at the [specified scope](../evidence.md). [Construction](../contribution-construction.md) supplies operations for a particular use.

<a id="target-69"></a>
## 69. Entry

making a representation available for immediate mental use.

**Candidate contributors:** Presenting the needed content immediately before use; retrieving it with a distinctive cue; translating it into an accessible form.

**Conditions and distinctions:** Availability requires comprehension and attention; physical presence on a page alone is insufficient.

<a id="target-70"></a>
## 70. Maintenance

keeping a representation available during another operation.

**Candidate contributors:** Rehearsing the relevant content; maintaining a visible reference; protecting it from competing input; organizing it into meaningful units.

**Conditions and distinctions:** External support changes supported performance; it does not by itself expand unaided capacity.

<a id="target-71"></a>
## 71. Updating

replacing outdated active content with current content.

**Candidate contributors:** An authoritative replacement value; an explicit supersession signal; comparison of old and current versions; removal of stale copies.

**Conditions and distinctions:** Without item identity, replacing a value can update the wrong object.

<a id="target-72"></a>
## 72. Binding

keeping the correct features attached to the correct item.

**Candidate contributors:** Stable names and locations; explicit feature-to-item links; integrated displays; rehearsing the relation as well as each feature.

**Conditions and distinctions:** Remembering all features separately does not preserve which belongs to which.

<a id="target-73"></a>
## 73. Ordering

changing the sequence in which active items are represented.

**Candidate contributors:** Numbering; spatial arrangement; a temporal or causal sequence; rehearsing transitions between adjacent elements.

**Conditions and distinctions:** A memorable order can still be the wrong execution order.

<a id="target-74"></a>
## 74. Chunking

treating multiple elements as one usable unit.

**Candidate contributors:** A learned pattern that encodes several elements jointly; a meaningful shared structure; a familiar abbreviation with recoverable contents.

**Conditions and distinctions:** A novel acronym may add another item instead of reducing load; the grouping must already be usable.

<a id="target-75"></a>
## 75. Interference

changing how much one active item disrupts another.

**Candidate contributors:** Reducing similarity between competing items; separating contexts or times; removing irrelevant content; distinctive item labels.

**Conditions and distinctions:** Interference reduction is different from proving general capacity growth [S05](../evidence.md#s05).

<a id="target-76"></a>
## 76. Comparison access

making relevant items available together.

**Candidate contributors:** Juxtaposing the relevant items; aligning corresponding dimensions; preserving common units and scope; externalizing one item while using another.

**Conditions and distinctions:** Two values are not comparable merely because they are adjacent; their meanings must align.

<a id="target-77"></a>
## 77. Release

removing no-longer-needed content from active use.

**Candidate contributors:** A completion marker; an explicit discard or defer decision; storing what must survive; removing obsolete prompts.

**Conditions and distinctions:** Premature release creates omissions if a downstream operation still needs the content.
