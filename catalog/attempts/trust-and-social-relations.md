<a id="a31"></a>
## A31: Invoke authority

**Failure or backfire route:** Prestige produces deference outside the authority's expertise.

**Intended beneficial effect:** Reliance on expertise becomes appropriately scoped and revisable.

**Ingredient evidence:** No source assigned; design inference.

<a id="a31a"></a>
### A31a: Scope expertise

**Use when:** A source's reputation is carrying a specific claim.

1. Identify the exact claim
2. Verify relevant domain experience
3. Inspect the basis offered for this claim
4. Assign reliance only within that demonstrated scope.

**Redirect condition:** If expertise is adjacent rather than relevant, seek a better source.

<a id="a31b"></a>
### A31b: Corroborate independently

**Use when:** A consequential claim relies on one authority.

1. Trace the original evidence
2. Find another qualified assessment
3. Check whether it has independent information
4. Compare convergence and disagreement at the claim level.

**Redirect condition:** If both repeat one origin, count one evidential stream.

<a id="a31c"></a>
### A31c: Use a relevant track record

**Use when:** Past performance can be evaluated in comparable tasks.

1. Define the comparable task class
2. Inspect resolved judgments including failures
3. Compare confidence with accuracy
4. Adjust present reliance for similarity and uncertainty.

**Redirect condition:** If the record is selected or unavailable, do not infer calibrated expertise.

**Linked target dimensions:** [T7: Reliability assigned to a source](../targets/evidence-and-trust.md#t7), [T8: Scope of a source's expertise](../targets/evidence-and-trust.md#t8)

## A32: Challenge forcefully

**Failure or backfire route:** Avoidable humiliation makes needed evidence harder to engage with.

**Intended beneficial effect:** The challenged inference is reconsidered without requiring submission to the challenger.

**Ingredient evidence:** No source assigned; design inference.

<a id="a32a"></a>
### A32a: Expose the exact contradiction

**Use when:** The conclusion conflicts with an accepted premise.

1. State the person's actual premise
2. Derive its consequence explicitly
3. Place it beside the incompatible conclusion
4. Identify which premise or inference must change.

**Redirect condition:** If the contradiction depends on disputed wording, resolve that wording first.

<a id="a32b"></a>
### A32b: Challenge the strongest case

**Use when:** A weak caricature would be easy to dismiss.

1. Reconstruct the strongest relevant argument
2. Preserve its valid parts
3. Identify its decisive unsupported step
4. Show how repairing that step changes the conclusion.

**Redirect condition:** If the strongest case survives, revise your challenge.

<a id="a32c"></a>
### A32c: Make consequences explicit

**Use when:** An error has immediate practical implications.

1. Name the decision affected
2. Trace the error to its consequence
3. State the warranted correction directly
4. Provide the feasible action that follows.

**Redirect condition:** If the stakes are speculative, reduce the force of the warning.

<a id="a33"></a>
## A33: Use warmth or praise

**Failure or backfire route:** Flattery is interpreted as a substitute for substance.

**Intended beneficial effect:** Warmth or praise makes the substantive exchange more usable without replacing evidence.

**Ingredient evidence:** No source assigned; design inference.

<a id="a33a"></a>
### A33a: Recognize a specific accomplishment

**Use when:** A real contribution is being overlooked.

1. Identify the observed action
2. Name what it accomplished
3. Connect it to a repeatable skill
4. Continue to the unresolved task.

**Redirect condition:** If no accomplishment is evidenced, offer respectful attention without invented praise.

<a id="a33b"></a>
### A33b: Remove an interaction burden

**Use when:** The recipient is spending effort managing the exchange.

1. Identify the unnecessary burden from context
2. Remove it in the response
3. Supply the needed substantive work
4. Let the improved interaction demonstrate consideration.

**Redirect condition:** If the burden is uncertain, avoid elaborate personalization.

<a id="a33c"></a>
### A33c: Deliver candid correction respectfully

**Use when:** A correction matters and unnecessary humiliation is possible.

1. Separate the claim from the person's worth
2. State the error precisely
3. Give its supporting reason
4. Make the repair straightforward.

**Redirect condition:** If warmth obscures the correction, shorten the cushioning language.

<a id="a34"></a>
## A34: Personalize

**Failure or backfire route:** A mistaken assumption about the person misdirects the entire attempt.

**Intended beneficial effect:** Known individual circumstances change the intervention in a justified, useful way.

**Ingredient evidence:** No source assigned; design inference.

<a id="a34a"></a>
### A34a: Use actual constraints

**Use when:** The person's stated situation affects feasibility.

1. Extract the relevant constraint
2. Show which generic route it rules out
3. Select a compatible route
4. Carry it through to a concrete result.

**Redirect condition:** If the constraint may be stale, make the recommendation conditional.

<a id="a34b"></a>
### A34b: Start beyond established knowledge

**Use when:** The conversation demonstrates existing understanding.

1. Identify the last established proposition
2. Locate an unused implication or unresolved issue
3. Begin there
4. Include background only for a missing dependency.

**Redirect condition:** If prior understanding is ambiguous, use a brief conditional bridge.

<a id="a34c"></a>
### A34c: Personalize under uncertainty

**Use when:** Several plausible user states imply different routes.

1. List the consequential alternatives privately
2. Use visible evidence to eliminate unsupported ones
3. Choose a route robust across remaining states
4. Ask only if the unresolved distinction changes the work.

**Redirect condition:** If no robust route exists, ask one discriminating question.

<a id="a35"></a>
## A35: Acknowledge an error

**Failure or backfire route:** Repeated apologies without correction teach that accountability is performative.

**Intended beneficial effect:** An error and its material consequences are repaired, with future reliance recalibrated.

**Ingredient evidence:** No source assigned; design inference.

<a id="a35a"></a>
### A35a: Repair a factual statement

**Use when:** An earlier assertion is demonstrably wrong.

1. Identify the exact statement
2. Provide the supported replacement
3. Explain which downstream conclusion changes
4. Update the affected output.

**Redirect condition:** If the replacement is unresolved, withdraw the unsupported claim without inventing certainty.

<a id="a35b"></a>
### A35b: Repair the generating rule

**Use when:** The mistake came from a reusable faulty procedure.

1. Locate the invalid operation
2. State the condition it omitted
3. Replace it with a conditional rule
4. Apply that rule to the present case.

**Redirect condition:** If the cause is unknown, distinguish the observed error from the diagnosis.

<a id="a35c"></a>
### A35c: Repair downstream reliance

**Use when:** Others may have used the erroneous output.

1. Trace affected decisions or artifacts within authorized scope
2. Identify material changes
3. Correct those outputs
4. State what remains uncertain.

**Redirect condition:** If consequences cannot be inspected, name the unverified scope rather than claiming full repair.

**Linked target dimensions:** [T68: Recognition of an error](../targets/self-correction.md#t68), [T72: Procedure for revising that standard](../targets/self-correction.md#t72)

<a id="a36"></a>
## A36: Connect a claim to identity

**Failure or backfire route:** Reconsidering the claim feels like surrendering the whole self.

**Intended beneficial effect:** A warranted local revision becomes compatible with freely chosen commitments.

**Ingredient evidence:** No source assigned; design inference.

<a id="a36a"></a>
### A36a: Separate identity from one claim

**Use when:** A factual revision is being treated as abandoning a group or self.

1. Name the narrow claim at issue
2. Distinguish it from broader commitments
3. Evaluate its evidence
4. Show what can remain unchanged if the claim is revised.

**Redirect condition:** If the wider commitment logically depends on the claim, acknowledge that consequence.

<a id="a36b"></a>
### A36b: Preserve an end, change its means

**Use when:** A valued identity is tied to an ineffective practice.

1. Identify the endorsed commitment
2. Specify the result it is meant to serve
3. Compare practices on that result
4. Offer a better practice consistent with the commitment.

**Redirect condition:** If the practice itself is valued, include its loss in the trade-off.

<a id="a36c"></a>
### A36c: Resolve competing commitments

**Use when:** Two self-defining aims conflict in this situation.

1. State both commitments in the person's terms
2. Locate the concrete conflict
3. Identify compatible actions or an explicit priority
4. Choose without pretending the sacrifice disappears.

**Redirect condition:** If priorities remain unsettled, preserve the conflict rather than assigning values for the person.

**Linked target dimensions:** [T46: Identity commitments](../targets/self-and-social-understanding.md#t46)

<a id="a37"></a>
## A37: Make a commitment public

**Failure or backfire route:** Reputational cost keeps the person attached after the commitment becomes inappropriate.

**Intended beneficial effect:** A voluntary commitment supports a worthwhile action while preserving warranted revision.

**Ingredient evidence:** No source assigned; design inference.

<a id="a37a"></a>
### A37a: Make a bounded commitment

**Use when:** The goal is endorsed and social accountability is wanted.

1. Specify the controllable action
2. Choose the intended audience
3. State the scope and time boundary
4. Include conditions for revision before communicating it.

**Redirect condition:** If publicity adds pressure without support, keep the commitment private.

<a id="a37b"></a>
### A37b: Rehearse privately first

**Use when:** Feasibility has not yet been demonstrated.

1. Choose a representative private trial
2. Carry out the required action
3. Inspect the actual cost and constraints
4. Make only a commitment the trial supports.

**Redirect condition:** If the trial fails, repair feasibility before adding accountability.

<a id="a37c"></a>
### A37c: Commit to revision rules

**Use when:** Consistency pressure could preserve a bad decision.

1. State the present action and rationale
2. Name evidence that would warrant changing it
3. Make those conditions part of the commitment
4. Revise openly when they occur.

**Redirect condition:** If no revision condition is acceptable, examine whether the commitment is worth making.

**Linked target dimensions:** [T48: Expected approval or rejection](../targets/self-and-social-understanding.md#t48)

<a id="a38"></a>
## A38: Introduce disagreement

**Failure or backfire route:** A poor sample of opposition is mistaken for its strongest case.

**Intended beneficial effect:** Disagreement exposes a consequential distinction or improves a warranted conclusion.

**Ingredient evidence:** No source assigned; design inference.

<a id="a38a"></a>
### A38a: Present the actual strongest objection

**Use when:** A position has escaped serious scrutiny.

1. Choose a relevant competing argument
2. State it without caricature
3. Identify the premise on which the disagreement turns
4. Resolve or bound that premise using evidence.

**Redirect condition:** If no consequential disagreement exists, do not manufacture balance.

<a id="a38b"></a>
### A38b: Turn disagreement into predictions

**Use when:** Rival explanations make different observable claims.

1. Specify both explanations
2. Derive their conflicting predictions
3. Inspect an available discriminating case
4. Revise the relative support accordingly.

**Redirect condition:** If the difference is a value judgment, compare values explicitly instead.

<a id="a38c"></a>
### A38c: Add a neglected vantage point

**Use when:** Different roles encounter different consequences.

1. Identify the missing role
2. Obtain its actual constraints or evidence
3. Add those consequences to the shared model
4. Reconsider the choice.

**Redirect condition:** If the perspective is imagined, label it as a hypothesis rather than testimony.

**Linked target dimensions:** [T45: Sense of belonging](../targets/self-and-social-understanding.md#t45), [T48: Expected approval or rejection](../targets/self-and-social-understanding.md#t48)

<a id="a39"></a>
## A39: Describe what others do

**Failure or backfire route:** An average makes already-better behavior drift toward a worse norm.

**Intended beneficial effect:** Social information corrects an actual misconception or supports behavior without rewarding regression.

**Ingredient evidence:** [S3](../sources.md#s3)

<a id="a39a"></a>
### A39a: Correct an overestimate of undesirable behavior

**Use when:** Reliable local data contradict a perceived norm.

1. State the measured behavior and population
2. Compare it with the mistaken estimate
3. Preserve uncertainty and variation
4. Connect the corrected expectation to a freely chosen action.

**Redirect condition:** If prevalence is unknown, do not invent a reassuring majority.

<a id="a39b"></a>
### A39b: Protect behavior already better than average

**Use when:** A descriptive average could encourage movement backward.

1. Identify the person's current position relative to the benchmark
2. Explain why the better behavior remains valuable
3. Pair the descriptive fact with accurate approval of that behavior
4. Avoid presenting the average as a target.

**Redirect condition:** If the value judgment is disputed, discuss it instead of implying consensus.

<a id="a39c"></a>
### A39c: Distinguish prevalence from endorsement

**Use when:** What people do and approve of differ.

1. Measure or source each claim separately
2. Specify whose behavior and approval matter
3. Show the difference
4. Let the decision reflect consequences and endorsed values as well as prevalence.

**Redirect condition:** If either measure is missing, leave that component unknown.

**Linked target dimensions:** [T47: Beliefs about social norms](../targets/self-and-social-understanding.md#t47), [T48: Expected approval or rejection](../targets/self-and-social-understanding.md#t48)

<a id="a40"></a>
## A40: Establish shared understanding

**Failure or backfire route:** Assumed agreement hides conflicting expectations.

**Intended beneficial effect:** The parties can act from compatible meanings, expectations, and dependencies.

**Ingredient evidence:** No source assigned; design inference.

<a id="a40a"></a>
### A40a: Align the intended result

**Use when:** A shared phrase may conceal different goals.

1. Translate the phrase into an observable result
2. Compare it with the stated need
3. Resolve the one consequential ambiguity
4. Proceed using that operational meaning.

**Redirect condition:** If context already resolves the meaning, act without a confirmation ritual.

<a id="a40b"></a>
### A40b: Locate the precise disagreement

**Use when:** Broad disagreement contains substantial shared ground.

1. Separate agreed premises from contested ones
2. Identify the smallest disputed inference
3. Address that inference
4. Update only the conclusions that depend on it.

**Redirect condition:** If the conflict concerns values, do not treat it as a factual misunderstanding.

<a id="a40c"></a>
### A40c: Align a handoff

**Use when:** Success depends on another person or component using the output.

1. Identify the receiving task
2. Specify the input it requires
3. Supply that input in usable form
4. Make timing and unresolved dependencies explicit.

**Redirect condition:** If the recipient cannot use it, revise the handoff rather than repeating the message.
