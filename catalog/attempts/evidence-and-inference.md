<a id="a11"></a>
## A11: Correct a false claim

**Failure or backfire route:** A bare denial leaves the old explanation available for later inference.

**Intended beneficial effect:** A supported correction changes the exact erroneous inference while preserving valid knowledge.

**Ingredient evidence:** [S4](../sources.md#s4)

<a id="a11a"></a>
### A11a: Correct one factual proposition

**Use when:** The claim, scope, and decisive evidence are identifiable.

1. State the correct proposition with its scope
2. Identify the conflicting part of the old claim
3. Show the decisive evidence and why it bears on that part
4. Apply the corrected proposition to the live inference.

**Redirect condition:** If evidence is contested, inspect the source or measurement issue before repeating the conclusion.

<a id="a11b"></a>
### A11b: Replace a causal explanation

**Use when:** The false claim fills an explanatory role.

1. Map what the old explanation accounts for
2. Preserve observations that remain true
3. Supply a supported alternative that accounts for them
4. Trace how the practical conclusion changes.

**Redirect condition:** If no alternative is known, retain the unexplained observation without restoring the false cause.

<a id="a11c"></a>
### A11c: Narrow a partly true claim

**Use when:** A valid claim has been generalized beyond its support.

1. Separate supported and unsupported cases
2. Identify the boundary from evidence
3. Rewrite the claim with that condition
4. Apply it to the disputed case.

**Redirect condition:** If the boundary is unknown, state the known domain and leave the extension unresolved.

**Linked target dimensions:** [T1: Factual beliefs](../targets/knowledge-and-uncertainty.md#t1)

## A12: Repeat a claim

**Failure or backfire route:** Familiarity is mistaken for additional evidence.

**Intended beneficial effect:** Repetition increases useful access or warranted support without being miscounted as new evidence.

**Ingredient evidence:** [S1](../sources.md#s1), [S10](../sources.md#s10)

<a id="a12a"></a>
### A12a: Repeat through retrieval

**Use when:** The issue is later access to verified information.

1. Present the accurate relation and qualification once
2. At a relevant later moment request its use or recall
3. Supply only the missing cue
4. Correct errors before another use.

**Redirect condition:** If recall is impossible, restore the prerequisite rather than increasing pressure.

<a id="a12b"></a>
### A12b: Repeat the qualification with the claim

**Use when:** The memorable version tends to lose its boundary.

1. Identify the exception whose loss changes meaning
2. Attach it directly to the compact claim
3. Use a boundary case during repetition
4. Preserve the pair in later summaries.

**Redirect condition:** If the qualification is too long, change the wording of the claim itself.

<a id="a12c"></a>
### A12c: Return with genuinely new support

**Use when:** Confidence should change because new evidence exists.

1. Identify the earlier evidential basis
2. Add the new independent observation
3. Distinguish its contribution from repeated sources
4. Revise confidence only by the additional support.

**Redirect condition:** If independence cannot be established, treat the repetition as a reminder.

<a id="a13"></a>
## A13: Speak confidently

**Failure or backfire route:** Certainty in delivery inflates certainty beyond the evidence.

**Intended beneficial effect:** Communicated certainty matches the argument or evidence while enabling appropriate action.

**Ingredient evidence:** No source assigned; design inference.

<a id="a13a"></a>
### A13a: State a proved consequence firmly

**Use when:** The relevant premises and inference are established.

1. List the necessary premises
2. Verify the inferential step
3. State the conclusion without unnecessary hedging
4. Place uncertainty on any premise that actually remains unsettled.

**Redirect condition:** If a premise is uncertain, state the result conditionally.

<a id="a13b"></a>
### A13b: Separate a strong finding from a tentative explanation

**Use when:** The result is better established than its proposed cause.

1. State the observation
2. State the proposed explanation separately
3. Name a competing explanation
4. Identify the observation that would distinguish them.

**Redirect condition:** If no distinction is currently available, preserve multiple causal accounts.

<a id="a13c"></a>
### A13c: Give a robust action under uncertainty

**Use when:** A choice is stable across the plausible range.

1. Identify the plausible range and available choices
2. Compare choices across that range
3. State the action that remains appropriate
4. Name the condition that would reverse it.

**Redirect condition:** If no choice is robust, expose the unresolved trade-off instead of projecting confidence.

**Linked target dimensions:** [T5: Confidence in a particular claim](../targets/knowledge-and-uncertainty.md#t5)

<a id="a14"></a>
## A14: Express uncertainty

**Failure or backfire route:** Local uncertainty becomes indiscriminate distrust of everything nearby.

**Intended beneficial effect:** The recipient can locate uncertainty and use what remains known.

**Ingredient evidence:** [S14](../sources.md#s14)

<a id="a14a"></a>
### A14a: Partition the account

**Use when:** Uncertainty in one component contaminates the whole.

1. Separate observations, interpretations, and unknowns
2. Attach each uncertainty to its component
3. Show what follows under every live interpretation
4. Preserve the conclusions common to them.

**Redirect condition:** If no common conclusion matters, identify the deciding unknown.

<a id="a14b"></a>
### A14b: Perform sensitivity analysis

**Use when:** A decision may depend on an uncertain value.

1. Specify the plausible range
2. Locate where the preferred choice changes
3. Check whether current uncertainty crosses that boundary
4. Seek precision only if it can change the choice.

**Redirect condition:** If the boundary cannot be located, expose the missing decision model.

<a id="a14c"></a>
### A14c: Separate obtainable and unresolved uncertainty

**Use when:** More inquiry may or may not be useful.

1. Name the unknown
2. List observations that could reduce it
3. Identify their availability and cost
4. Choose a feasible observation or a decision rule that tolerates the remaining uncertainty.

**Redirect condition:** If no observation distinguishes alternatives, do not promise resolution through more explanation.

**Linked target dimensions:** [T4: Uncertainty ranges](../targets/knowledge-and-uncertainty.md#t4), [T6: Recognition of what is unknown](../targets/knowledge-and-uncertainty.md#t6), [T42: Tolerance of uncertainty](../targets/emotion-and-appraisal.md#t42)

<a id="a15"></a>
## A15: Present much evidence

**Failure or backfire route:** Correlated or weak examples create a false impression of independent support.

**Intended beneficial effect:** Evidence changes the relevant comparison without double-counting or obscuring the decisive issue.

**Ingredient evidence:** No source assigned; design inference.

<a id="a15a"></a>
### A15a: Lead with a discriminating observation

**Use when:** One finding separates the main accounts.

1. Write the competing predictions
2. Select an observation where they differ
3. Inspect its quality
4. Show exactly which account it favors and by how much the evidence permits.

**Redirect condition:** If both predict it, do not present it as decisive.

<a id="a15b"></a>
### A15b: Combine independent contributions

**Use when:** Several observations each supply new information.

1. Trace each item to its originating observation
2. Group dependent reports
3. Compare independent contributions
4. Summarize the combined direction with unresolved limitations.

**Redirect condition:** If sources share an origin, count the underlying observation once.

<a id="a15c"></a>
### A15c: Reconcile conflicting evidence

**Use when:** Credible studies or observations disagree.

1. Align their populations, interventions, measures, and timing
2. Locate the differences that could explain the conflict
3. Separate genuine disagreement from different questions
4. Retain conditional conclusions where needed.

**Redirect condition:** If the difference remains unexplained, report the conflict rather than selecting the preferred result.

**Linked target dimensions:** [T1: Factual beliefs](../targets/knowledge-and-uncertainty.md#t1), [T5: Confidence in a particular claim](../targets/knowledge-and-uncertainty.md#t5)

<a id="a16"></a>
## A16: Cite sources

**Failure or backfire route:** Prestige substitutes for checking whether a source supports the claim.

**Intended beneficial effect:** The recipient can inspect the evidence supporting the specific claim.

**Ingredient evidence:** No source assigned; design inference.

<a id="a16a"></a>
### A16a: Bind each consequential claim to support

**Use when:** The answer depends on externally verifiable facts.

1. Identify the claims whose failure changes the conclusion
2. Open their primary sources
3. Locate the relevant evidence
4. Attach a direct citation and preserve the source's actual scope.

**Redirect condition:** If no source supports a claim, remove it or mark it as an inference.

<a id="a16b"></a>
### A16b: Audit the source's applicability

**Use when:** A respected source may concern the wrong case.

1. Match the source's population, date, method, and outcome to the current question
2. Identify mismatches
3. Retain supported components
4. Limit the resulting conclusion.

**Redirect condition:** If the mismatch controls the answer, find more applicable evidence.

<a id="a16c"></a>
### A16c: Trace a citation chain to origin

**Use when:** Many references may repeat one unsupported assertion.

1. Follow the pivotal assertion to its earliest accessible evidence
2. Distinguish reporting from new observation
3. Inspect that evidence
4. Update the claim using its actual support.

**Redirect condition:** If the origin cannot be inspected, mark the support unverified rather than laundering it through citations.

**Linked target dimensions:** [T7: Reliability assigned to a source](../targets/evidence-and-trust.md#t7), [T8: Scope of a source's expertise](../targets/evidence-and-trust.md#t8), [T12: Willingness to verify](../targets/evidence-and-trust.md#t12)

## A17: Give a counterexample

**Failure or backfire route:** One exception is used to reject more than it logically refutes.

**Intended beneficial effect:** The counterexample defeats or bounds only the inference it logically addresses.

**Ingredient evidence:** No source assigned; design inference.

<a id="a17a"></a>
### A17a: Refute a universal claim

**Use when:** The proposition asserts all, none, always, or impossible.

1. Write the proposition with explicit conditions
2. Construct or verify a case meeting those conditions
3. Show the contrary result
4. Withdraw the universal assertion.

**Redirect condition:** If a condition is not met, the case does not refute the assertion.

<a id="a17b"></a>
### A17b: Repair the boundary

**Use when:** A useful generalization has a meaningful exception.

1. Compare the exception with valid cases
2. Identify a condition explaining the difference
3. Formulate the narrower rule
4. Examine another case near the new boundary.

**Redirect condition:** If no stable boundary is supported, retain a probabilistic or unresolved account.

<a id="a17c"></a>
### A17c: Correct an overextended intuition

**Use when:** An intuitive rule is useful in some settings and misleading in others.

1. Present a familiar case where the intuition works
2. Change one consequential condition
3. Calculate or trace the changed outcome
4. State which feature controls transfer.

**Redirect condition:** If the revised case is unrealistic for the task, choose a relevant boundary case.

**Linked target dimensions:** [T21: Boundaries](../targets/representation.md#t21)

<a id="a18"></a>
## A18: Ask for a mechanism

**Failure or backfire route:** Fluent improvisation creates a false sense of explanation.

**Intended beneficial effect:** A mechanism account supports a discriminating prediction and exposes unresolved links.

**Ingredient evidence:** [S7](../sources.md#s7)

<a id="a18a"></a>
### A18a: Trace the proposed cause to the outcome

**Use when:** An explanation contains unnamed intermediate steps.

1. State the cause and outcome
2. Fill each necessary intermediate transition with a literal operation
3. Mark unsupported transitions
4. Derive an observable consequence of the weakest disputed link.

**Redirect condition:** If a transition cannot be specified, label the mechanism incomplete.

<a id="a18b"></a>
### A18b: Compare rival mechanisms

**Use when:** Several stories explain the same observation.

1. Write each mechanism as a sequence
2. Locate where their predicted consequences diverge
3. Check the available evidence at that point
4. Preserve the surviving accounts.

**Redirect condition:** If the mechanisms make identical available predictions, do not choose by narrative fluency.

<a id="a18c"></a>
### A18c: Build a bounded model

**Use when:** The mechanism can be represented with explicit inputs and rules.

1. Choose a small case preserving the causal relationship
2. State the rules
3. Calculate or simulate the outcome
4. Compare with the target behavior and identify omitted factors.

**Redirect condition:** If the model matches only after ad hoc changes, expose those changes as new assumptions.

**Linked target dimensions:** [T2: Causal explanations](../targets/knowledge-and-uncertainty.md#t2)

<a id="a19"></a>
## A19: Ask for reasons

**Failure or backfire route:** The person rehearses defenses without examining what would decide the issue.

**Intended beneficial effect:** Reasons reveal what actually governs the judgment and what could change it.

**Ingredient evidence:** [S7](../sources.md#s7)

<a id="a19a"></a>
### A19a: Find the deciding reason

**Use when:** A list of reasons obscures which one matters.

1. List the stated reasons
2. Consider the choice with each removed
3. Identify which removals alter the judgment
4. Examine those reasons first.

**Redirect condition:** If no removal matters, look for an unstated governing concern.

<a id="a19b"></a>
### A19b: Separate factual and evaluative reasons

**Use when:** Evidence disputes conceal disagreements about priorities.

1. Classify each reason as factual, causal, or evaluative
2. Resolve factual claims with evidence
3. Express evaluative trade-offs explicitly
4. Show which disagreement remains.

**Redirect condition:** If priorities differ, do not pretend another fact alone resolves them.

<a id="a19c"></a>
### A19c: Use the person's own accepted premises

**Use when:** The conclusion conflicts with another accepted commitment.

1. State both commitments accurately
2. Derive their joint consequence
3. Identify the conflict in a concrete case
4. Make the available revisions explicit.

**Redirect condition:** If the commitments are conditional rather than conflicting, clarify their different conditions.

<a id="a20"></a>
## A20: Present several perspectives

**Failure or backfire route:** Unequal accounts are treated as equally supported.

**Intended beneficial effect:** Alternative frames reveal consequential differences while preserving evidential discrimination.

**Ingredient evidence:** No source assigned; design inference.

<a id="a20a"></a>
### A20a: Expose an omission

**Use when:** The current frame hides a relevant part of the situation.

1. List what the current frame represents
2. Identify a consequential omitted factor
3. Choose a frame that makes that factor explicit
4. Compare how the available actions change.

**Redirect condition:** If the alternative adds no consequential difference, omit it.

<a id="a20b"></a>
### A20b: Extract what survives multiple representations

**Use when:** A conclusion may depend on a particular description.

1. Express the same situation through two materially different frames
2. Derive the conclusion within each
3. Identify common results and frame-dependent results
4. Investigate the latter's assumptions.

**Redirect condition:** If translations change the underlying facts, repair the translation before comparing.

<a id="a20c"></a>
### A20c: Choose a frame conditionally

**Use when:** Different representations serve different operations.

1. Specify the operation needed now
2. List what each frame makes easy or obscures
3. Select the frame fitting that operation
4. Preserve access to another frame for its relevant condition.

**Redirect condition:** If the operation itself is mistaken, revise the target before selecting a frame.
