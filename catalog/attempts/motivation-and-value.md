<a id="a41"></a>
## A41: Explain personal relevance

**Failure or backfire route:** Imposed motives make the activity feel alien or controlling.

**Intended beneficial effect:** The connection to a valued concern is real enough to change attention, effort, or task choice.

**Ingredient evidence:** [S9](../sources.md#s9)

<a id="a41a"></a>
### A41a: Generate a personal connection

**Use when:** The material has plausible applications but none feels relevant.

1. Identify a concern the person already values
2. Select a specific concept from the material
3. Let the person connect it to that concern when participation is useful
4. Use the connection in a concrete task.

**Redirect condition:** If no honest connection appears, do not manufacture relevance.

<a id="a41b"></a>
### A41b: Trace a real consequence

**Use when:** The person does not see how the issue affects an existing goal.

1. Name the goal from context
2. Trace the issue through an explicit causal chain
3. Identify the decision or action it changes
4. Supply the information needed for that action.

**Redirect condition:** If a causal link is unsupported, qualify or remove it.

<a id="a41c"></a>
### A41c: Replace an irrelevant task

**Use when:** The assigned task does not serve an endorsed purpose.

1. Specify its intended benefit
2. Compare that benefit with present priorities
3. Find a task that serves the same legitimate requirement more directly
4. Replace or retire the original where feasible.

**Redirect condition:** If replacement is unavailable, distinguish the external requirement from personal value.

**Linked target dimensions:** [T33: Interest](../targets/motivation-and-value.md#t33), [T37: Attraction or aversion](../targets/emotion-and-appraisal.md#t37)

<a id="a42"></a>
## A42: Describe an attractive future

**Failure or backfire route:** Imagined success substitutes for preparation or feasible action.

**Intended beneficial effect:** A future scenario informs feasible action without substituting imagined success for progress.

**Ingredient evidence:** No source assigned; design inference.

<a id="a42a"></a>
### A42a: Contrast the future with an obstacle

**Use when:** An attractive result is clear but action is stalled.

1. Describe the desired observable result
2. Identify the main present obstacle
3. Select an action that changes that obstacle
4. Connect the scenario to that action.

**Redirect condition:** If the obstacle cannot be changed, revise the route or target.

<a id="a42b"></a>
### A42b: Work backward from arrival

**Use when:** The destination lacks an executable path.

1. Specify what must be true at arrival
2. Work backward through prerequisites
3. Identify the next attainable prerequisite
4. Place it in the current schedule or workflow.

**Redirect condition:** If backward reasoning reaches an unsupported leap, leave that link unresolved.

<a id="a42c"></a>
### A42c: Compare plausible futures

**Use when:** One appealing scenario dominates despite uncertainty.

1. Construct success, partial-success, and failure scenarios
2. Include their costs and requirements
3. Identify actions useful across them
4. Choose a robust next move.

**Redirect condition:** If scenarios lack evidential grounding, use them to expose assumptions, not predict probabilities.

**Linked target dimensions:** [T34: Expected value of success](../targets/motivation-and-value.md#t34)

<a id="a43"></a>
## A43: Warn about danger

**Failure or backfire route:** Threat feels unmanageable and promotes avoidance.

**Intended beneficial effect:** Concern becomes proportionate to evidence and connected to a feasible protective action.

**Ingredient evidence:** No source assigned; design inference.

<a id="a43a"></a>
### A43a: Pair a hazard with control

**Use when:** A supported danger is underestimated and action is available.

1. State the hazard and relevant exposure
2. Explain the evidence without exaggeration
3. Give a feasible action that reduces it
4. Specify what that action does and does not resolve.

**Redirect condition:** If no useful action follows, reconsider whether additional alarm helps.

<a id="a43b"></a>
### A43b: Respond conditionally to uncertainty

**Use when:** Risk is unresolved but a precaution may be worthwhile.

1. Separate established facts from uncertain scenarios
2. Identify the consequence that matters
3. Compare precaution cost with plausible avoided harm
4. State the conditions for escalating or stopping.

**Redirect condition:** If the precaution itself has substantial costs, include them explicitly.

<a id="a43c"></a>
### A43c: Reduce a false alarm

**Use when:** The person is already alert beyond what the evidence supports.

1. Identify the feared event
2. Distinguish its possibility from its likelihood
3. Supply relevant limiting evidence
4. Redirect attention to the remaining actionable risk.

**Redirect condition:** If uncertainty remains large, do not replace alarm with certainty.

**Linked target dimensions:** [T39: Perceived threat](../targets/emotion-and-appraisal.md#t39)

<a id="a44"></a>
## A44: Assign responsibility

**Failure or backfire route:** A specific mistake becomes a global judgment of worthlessness.

**Intended beneficial effect:** Responsibility produces a feasible contribution or repair rather than diffuse self-blame.

**Ingredient evidence:** No source assigned; design inference.

<a id="a44a"></a>
### A44a: Bound personal control

**Use when:** A broad outcome is being assigned to one person.

1. Separate controllable actions from external conditions
2. Identify the person's actual contribution
3. Specify the next controllable action
4. Judge responsibility at that level.

**Redirect condition:** If no control exists, shift from blame to adaptation or support.

<a id="a44b"></a>
### A44b: Convert fault into repair

**Use when:** A preventable action caused a concrete problem.

1. Name the action and consequence
2. Identify what can still be repaired
3. Carry out the feasible repair
4. Revise the procedure that produced the error.

**Redirect condition:** If repair is impossible, preserve the lesson without promising reversal.

<a id="a44c"></a>
### A44c: Allocate shared responsibility

**Use when:** Several actors or conditions jointly produce the outcome.

1. Map their causal roles
2. Distinguish authority from obligation
3. Assign feasible contributions within actual authority
4. Identify unresolved coordination needs.

**Redirect condition:** If roles cannot cover the required work, change resources or expectations.

**Linked target dimensions:** [T44: Sense of agency](../targets/self-and-social-understanding.md#t44)

<a id="a45"></a>
## A45: Reassure

**Failure or backfire route:** Unsupported comfort suppresses necessary investigation or preparation.

**Intended beneficial effect:** Reassurance changes an unsupported appraisal while preserving recognition of unresolved facts.

**Ingredient evidence:** No source assigned; design inference.

<a id="a45a"></a>
### A45a: Give supported bounds

**Use when:** The feared conclusion exceeds the evidence.

1. State exactly what is feared
2. Identify evidence that limits that inference
3. Specify the narrower remaining uncertainty
4. Connect the bound to the current decision.

**Redirect condition:** If the evidence does not limit the fear, do not offer factual reassurance.

<a id="a45b"></a>
### A45b: Make the next step controllable

**Use when:** Distress partly concerns having no available action.

1. Name the immediate practical difficulty
2. Identify one available action
3. Remove its first execution obstacle
4. Explain the result that action can realistically produce.

**Redirect condition:** If action cannot resolve the uncertainty, say what it can accomplish.

<a id="a45c"></a>
### A45c: Offer dependable support

**Use when:** Outcome certainty is unavailable but specific assistance is possible.

1. Separate the unknown outcome from available support
2. Specify what assistance can actually be provided
3. Provide it within authorization
4. Avoid promises beyond that capacity.

**Redirect condition:** If the support is unavailable, help locate a feasible alternative.

**Linked target dimensions:** [T40: Perceived safety](../targets/emotion-and-appraisal.md#t40)

<a id="a46"></a>
## A46: Build confidence

**Failure or backfire route:** Promises create expectations unsupported by ability or circumstances.

**Intended beneficial effect:** Confidence becomes better matched to demonstrated capability and available resources.

**Ingredient evidence:** [S11](../sources.md#s11)

<a id="a46a"></a>
### A46a: Use representative mastery evidence

**Use when:** Competence is underestimated despite relevant performance.

1. Choose a representative completed task
2. Identify the skill it demonstrates
3. Compare its difficulty with the upcoming task
4. Increase confidence only within the supported scope.

**Redirect condition:** If the tasks differ materially, identify the missing skill.

<a id="a46b"></a>
### A46b: Calibrate confidence

**Use when:** Certainty and accuracy have diverged across comparable judgments.

1. Record confidence before resolution
2. Compare with actual outcomes across enough cases
3. Identify systematic overconfidence or underconfidence
4. Adjust future estimates in that task class.

**Redirect condition:** If observations are too few, preserve a wider range.

<a id="a46c"></a>
### A46c: Repair the conditions for success

**Use when:** Low confidence reflects a real resource or skill gap.

1. Identify the missing prerequisite
2. Supply training, access, time, or support
3. Complete a representative step
4. Revise the capability estimate from that new evidence.

**Redirect condition:** If the prerequisite remains missing, do not substitute encouragement.

**Linked target dimensions:** [T3: Predictions](../targets/knowledge-and-uncertainty.md#t3), [T10: Trust in one's own judgment](../targets/evidence-and-trust.md#t10), [T36: Willingness to expend effort](../targets/motivation-and-value.md#t36), [T43: Estimate of one's competence](../targets/self-and-social-understanding.md#t43)

## A47: Offer a reward

**Failure or backfire route:** The reward displaces the reason the person originally cared.

**Intended beneficial effect:** An incentive supports the intended outcome without making the proxy the objective.

**Ingredient evidence:** No source assigned; design inference.

<a id="a47a"></a>
### A47a: Offset a real cost

**Use when:** An endorsed action has an immediate practical burden.

1. Identify the burden
2. Choose support proportionate to that burden
3. Tie support to the intended action without hidden conditions
4. Inspect whether the action becomes feasible.

**Redirect condition:** If the obstacle is dislike of the goal, reconsider the goal.

<a id="a47b"></a>
### A47b: Make progress informative

**Use when:** The person lacks useful feedback on developing competence.

1. Define the skill being improved
2. Observe a concrete improvement
3. Explain the action that produced it
4. Make the next attainable improvement visible.

**Redirect condition:** If performance has not improved, offer accurate diagnostic feedback instead of praise.

<a id="a47c"></a>
### A47c: Plan the end of a reward

**Use when:** Behavior should continue after an external incentive ends.

1. Identify what will sustain the behavior afterward
2. Build that support while the incentive exists
3. Reduce the incentive under stated conditions
4. Observe continuation separately from rewarded performance.

**Redirect condition:** If continuation fails, report incentive-dependent behavior rather than habit.

<a id="a48"></a>
## A48: Compare with other people

**Failure or backfire route:** Comparison produces discouragement or premature satisfaction.

**Intended beneficial effect:** Comparison supplies an attainable, relevant lesson without confusing status with worth.

**Ingredient evidence:** No source assigned; design inference.

<a id="a48a"></a>
### A48a: Compare with a personal baseline

**Use when:** The person's own past performance is comparable.

1. Choose the same outcome and measurement
2. Account for changed conditions
3. Locate an actual improvement or decline
4. Connect it to a controllable process.

**Redirect condition:** If conditions differ too much, avoid attributing the change to skill.

<a id="a48b"></a>
### A48b: Use a matched peer

**Use when:** A peer's example could reveal an available method.

1. Match relevant resources and starting conditions
2. Compare processes as well as outcomes
3. Identify a transferable operation
4. Adapt it to the present constraints.

**Redirect condition:** If the peer has inaccessible advantages, do not present the result as a fair benchmark.

<a id="a48c"></a>
### A48c: Compare methods

**Use when:** Status rankings obscure how results are produced.

1. Hold the task constant
2. Contrast two methods and their requirements
3. Identify the operation explaining the difference
4. Choose according to the actual task and resources.

**Redirect condition:** If the causal operation is unknown, describe the difference without inventing an explanation.

<a id="a49"></a>
## A49: Clarify values

**Failure or backfire route:** The communicator's priorities replace the person's considered priorities.

**Intended beneficial effect:** Values become explicit enough to guide a concrete trade-off while remaining the person's own.

**Ingredient evidence:** No source assigned; design inference.

<a id="a49a"></a>
### A49a: Use a real trade-off

**Use when:** Several attractive values cannot all be maximized.

1. Choose the live decision
2. Describe feasible alternatives and sacrifices
3. Identify which sacrifice the person accepts
4. Express the resulting priority conditionally for this situation.

**Redirect condition:** If no choice is endorsed, preserve the unresolved trade-off.

<a id="a49b"></a>
### A49b: Interpret behavior with context

**Use when:** Actions seem inconsistent with stated values.

1. Identify the behavior and circumstances
2. Inspect constraints and immediate incentives
3. Distinguish inability from preference
4. Revise the interpretation only where the evidence supports it.

**Redirect condition:** If multiple explanations remain, do not declare a hidden true value.

<a id="a49c"></a>
### A49c: Resolve competing goals

**Use when:** Two endorsed goals compete for resources.

1. Specify each goal's concrete benefit
2. Estimate the resource conflict
3. Search for a compatible allocation
4. Choose an explicit priority where conflict remains.

**Redirect condition:** If the conflict is temporary, use a time-bounded allocation rather than a permanent ranking.

**Linked target dimensions:** [T31: Goals](../targets/motivation-and-value.md#t31), [T32: Priorities](../targets/motivation-and-value.md#t32), [T34: Expected value of success](../targets/motivation-and-value.md#t34), [T35: Costs considered acceptable](../targets/motivation-and-value.md#t35), [T37: Attraction or aversion](../targets/emotion-and-appraisal.md#t37), [T49: Comparison criteria](../targets/decision-processes.md#t49), [T50: Weights assigned to criteria](../targets/decision-processes.md#t50)

<a id="a50"></a>
## A50: Give an activity meaning

**Failure or backfire route:** A limited task becomes an all-consuming identity obligation.

**Intended beneficial effect:** Meaning rests on a credible connection between the activity and an endorsed contribution.

**Ingredient evidence:** No source assigned; design inference.

<a id="a50a"></a>
### A50a: Trace actual contribution

**Use when:** A task's effect on others or a larger result is obscure.

1. Identify the recipient or downstream result
2. Trace what the task contributes
3. Verify that the contribution matters
4. Connect the current action to that contribution.

**Redirect condition:** If the contribution is negligible, improve the task or reduce its claimed importance.

<a id="a50b"></a>
### A50b: Choose a purpose

**Use when:** Several legitimate purposes could organize the activity.

1. List purposes consistent with the actual task
2. Compare them with stated values
3. Select an endorsed purpose
4. Adapt the activity so it actually serves that purpose.

**Redirect condition:** If none is endorsed, avoid imposing a motivational story.

<a id="a50c"></a>
### A50c: Bound the role

**Use when:** A meaningful activity has become an unlimited obligation.

1. Name the contribution worth preserving
2. Identify the person's finite role
3. Set a feasible scope
4. Retain the contribution without claiming responsibility for the entire outcome.

**Redirect condition:** If the limited role cannot matter, redesign the contribution.

**Linked target dimensions:** [T31: Goals](../targets/motivation-and-value.md#t31)
