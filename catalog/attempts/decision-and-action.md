<a id="a51"></a>
## A51: Expand the option set

**Failure or backfire route:** More possibilities make a previously manageable decision stall.

**Intended beneficial effect:** The option set gains a feasible, materially different alternative.

**Ingredient evidence:** No source assigned; design inference.

<a id="a51a"></a>
### A51a: Relax an assumed constraint

**Use when:** Existing options share an unverified restriction.

1. Identify the common restriction
2. Check its actual source
3. Remove or modify it where possible
4. Construct an option enabled by the change.

**Redirect condition:** If the restriction is binding, retain it and search elsewhere.

<a id="a51b"></a>
### A51b: Recombine useful parts

**Use when:** Existing options each satisfy different needs.

1. Separate their useful components
2. Check compatibility between components
3. Assemble a feasible combination
4. Compare its total costs and interactions.

**Redirect condition:** If the parts conflict, preserve separate alternatives.

<a id="a51c"></a>
### A51c: Dissolve a false binary

**Use when:** Only two options are considered despite continuous or staged choices.

1. Identify the variable behind the binary
2. Consider partial, staged, reversible, and deferred choices
3. Eliminate infeasible ones
4. Compare the remaining choices against the actual criteria.

**Redirect condition:** If the decision is truly binary, focus on evidence and trade-offs.

**Linked target dimensions:** [T25: Options considered](../targets/possibilities.md#t25), [T27: Constraints believed fixed](../targets/possibilities.md#t27)

<a id="a52"></a>
## A52: Offer a default

**Failure or backfire route:** An unexamined default forecloses a better-fitting choice.

**Intended beneficial effect:** A starting option reduces effort while fitting the person's needs and remaining inspectable.

**Ingredient evidence:** No source assigned; design inference.

<a id="a52a"></a>
### A52a: Choose a justified starting option

**Use when:** Known needs strongly favor one conventional choice.

1. Extract the relevant needs
2. Eliminate options violating them
3. Select the supported starting option
4. State the condition under which it should be changed.

**Redirect condition:** If needs do not distinguish options, avoid pretending one is universally best.

<a id="a52b"></a>
### A52b: Use a reversible default

**Use when:** A low-cost initial choice enables learning through use.

1. Identify a readily reversible option
2. Bound its initial cost
3. Specify the information use will reveal
4. State a switch condition before starting.

**Redirect condition:** If switching is costly, investigate before defaulting.

<a id="a52c"></a>
### A52c: Differentiate by circumstance

**Use when:** Different users predictably need different defaults.

1. Identify the few consequential circumstance differences
2. Map each to a fitting option
3. Select using known context
4. Expose the relevant alternative when context is uncertain.

**Redirect condition:** If the mapping is weak, present the real trade-off instead.

**Linked target dimensions:** [T53: Threshold for accepting an option](../targets/decision-processes.md#t53)

<a id="a53"></a>
## A53: Rank decision criteria

**Failure or backfire route:** A convenient metric displaces the actual objective.

**Intended beneficial effect:** Criteria distinguish acceptable options and support a choice consistent with endorsed priorities.

**Ingredient evidence:** No source assigned; design inference.

<a id="a53a"></a>
### A53a: Separate constraints from preferences

**Use when:** A weighted score could hide an unacceptable failure.

1. List nonnegotiable requirements
2. Eliminate violating options
3. Identify preferences among remaining options
4. Compare only feasible candidates.

**Redirect condition:** If no option survives, renegotiate a requirement or develop another option.

<a id="a53b"></a>
### A53b: Weight meaningful differences

**Use when:** Labels such as quality or cost have arbitrary weights.

1. Specify the actual best-to-worst range of each criterion
2. Compare the value of those swings
3. Assign weights only to those defined ranges
4. Evaluate the options consistently.

**Redirect condition:** If weights are unstable, use ranges and identify robust choices.

<a id="a53c"></a>
### A53c: Locate sensitive judgments

**Use when:** Small rating changes may reverse the recommendation.

1. Identify uncertain scores and weights
2. Vary them over defensible ranges
3. Find which changes reverse the ranking
4. Resolve only those with practical importance.

**Redirect condition:** If no realistic change reverses the choice, stop refining the score.

**Linked target dimensions:** [T11: Threshold for updating](../targets/evidence-and-trust.md#t11), [T34: Expected value of success](../targets/motivation-and-value.md#t34), [T35: Costs considered acceptable](../targets/motivation-and-value.md#t35), [T49: Comparison criteria](../targets/decision-processes.md#t49), [T50: Weights assigned to criteria](../targets/decision-processes.md#t50), [T51: Rule used to choose](../targets/decision-processes.md#t51), [T53: Threshold for accepting an option](../targets/decision-processes.md#t53)

## A54: Create an if-then plan

**Failure or backfire route:** An inappropriate cue triggers action after circumstances change.

**Intended beneficial effect:** The relevant cue leads to an endorsed, feasible action when the opportunity occurs.

**Ingredient evidence:** [S15](../sources.md#s15), [S23](../sources.md#s23)

<a id="a54a"></a>
### A54a: Connect a cue to an available action

**Use when:** Forgetting or ambiguity at the moment of action is the main obstacle.

1. Choose a cue that will actually occur
2. Specify one observable action
3. Verify that resources will be available then
4. Place the cue-action link where it will be encountered.

**Redirect condition:** If motivation or access is missing, repair that prerequisite first.

<a id="a54b"></a>
### A54b: Include an obstacle branch

**Use when:** A known recurring obstacle disrupts execution.

1. Identify the specific obstacle
2. Choose a feasible alternative action or time
3. Attach it to the obstacle condition
4. Preserve the original purpose in the fallback.

**Redirect condition:** If neither branch is feasible, revise the plan before relying on it.

<a id="a54c"></a>
### A54c: Include a stop or revision branch

**Use when:** Repeated action can become inappropriate when circumstances change.

1. Specify the action's valid conditions
2. Name an observable invalidating condition
3. Attach a stop-and-review response
4. Make resumption depend on restored prerequisites.

**Redirect condition:** If the condition cannot be observed, use a bounded review interval.

**Linked target dimensions:** [T36: Willingness to expend effort](../targets/motivation-and-value.md#t36), [T55: Conditions that trigger starting](../targets/action-control.md#t55), [T56: Conditions that inhibit an action](../targets/action-control.md#t56), [T59: Conditions for changing course](../targets/action-control.md#t59), [T60: Degree of automaticity](../targets/action-control.md#t60)

## A55: Make the first step smaller

**Failure or backfire route:** The simplified step no longer contributes to the real objective.

**Intended beneficial effect:** The smaller action removes a real initiation barrier and advances the valued result.

**Ingredient evidence:** No source assigned; design inference.

<a id="a55a"></a>
### A55a: Specify the first physical operation

**Use when:** The task is too abstract to begin.

1. Name the intended output
2. Identify the first visible operation
3. Supply its required input
4. Perform or schedule that operation in the available context.

**Redirect condition:** If the first operation is easy but avoided, inspect value or competing costs.

<a id="a55b"></a>
### A55b: Complete a prerequisite

**Use when:** The visible task cannot begin yet.

1. List what starting requires
2. Identify one missing prerequisite
3. Choose its smallest complete repair
4. Connect completion directly to the original task.

**Redirect condition:** If the repair cannot enable progress, it is busywork rather than a useful small step.

<a id="a55c"></a>
### A55c: Take a bounded informative step

**Use when:** A large commitment is blocked by consequential uncertainty.

1. Identify the uncertainty
2. Choose a low-cost action that resolves it
3. State which result implies which next move
4. Take the action within the cost bound.

**Redirect condition:** If the result cannot change a decision, choose a different step.

**Linked target dimensions:** [T28: Actions perceived as available](../targets/possibilities.md#t28), [T44: Sense of agency](../targets/self-and-social-understanding.md#t44), [T55: Conditions that trigger starting](../targets/action-control.md#t55)

<a id="a56"></a>
## A56: Specify a sequence

**Failure or backfire route:** Rigid compliance continues despite evidence that the sequence is wrong.

**Intended beneficial effect:** Actions occur in an order that respects dependencies and exposes costly errors early.

**Ingredient evidence:** No source assigned; design inference.

<a id="a56a"></a>
### A56a: Order by prerequisites

**Use when:** Later steps require earlier outputs.

1. List required outputs
2. Connect each to its inputs
3. Place prerequisites before dependent actions
4. Execute from the earliest currently feasible step.

**Redirect condition:** If dependencies form a cycle, redesign a step or obtain an external input.

<a id="a56b"></a>
### A56b: Place a consequential checkpoint

**Use when:** An early error would be expensive to propagate.

1. Identify the first costly commitment
2. Locate the cheapest meaningful check before it
3. Perform that check
4. Continue or repair according to its result.

**Redirect condition:** If the check merely repeats the implementation, replace it with independent evidence.

<a id="a56c"></a>
### A56c: Coordinate independent work

**Use when:** Several operations can proceed without each other's outputs.

1. Separate independent operations from dependent ones
2. Assign available resources without conflicts
3. Perform independent work concurrently where authorized
4. Join results before dependent decisions.

**Redirect condition:** If concurrency creates interference, sequence the conflicting operations.

**Linked target dimensions:** [T12: Willingness to verify](../targets/evidence-and-trust.md#t12), [T57: Sequence of actions](../targets/action-control.md#t57)

<a id="a57"></a>
## A57: Create a deadline

**Failure or backfire route:** Artificial urgency produces a rash commitment.

**Intended beneficial effect:** A time boundary improves action timing without forcing avoidable error.

**Ingredient evidence:** No source assigned; design inference.

<a id="a57a"></a>
### A57a: Honor a real expiration

**Use when:** An opportunity or requirement has a genuine deadline.

1. Verify the deadline
2. Work backward from required completion
3. Reserve time for necessary dependencies
4. Begin the latest safe feasible sequence.

**Redirect condition:** If completion is infeasible, revise scope or communicate the actual constraint.

<a id="a57b"></a>
### A57b: Bound inquiry

**Use when:** Further deliberation has declining practical value.

1. Identify information still capable of changing the choice
2. Estimate how long obtaining it takes
3. Allocate a bounded search period
4. Choose using the best supported result when that period ends.

**Redirect condition:** If new consequential evidence appears, use the predeclared extension condition.

<a id="a57c"></a>
### A57c: Set a checkpoint instead of forcing a verdict

**Use when:** The final decision is not yet adequately supported.

1. Identify what can be completed now
2. Set a deadline for that intermediate result
3. Specify the evidence needed next
4. Reserve the final decision until its prerequisites hold.

**Redirect condition:** If delay itself is costly, choose an explicitly provisional action.

**Linked target dimensions:** [T38: Sense of urgency](../targets/emotion-and-appraisal.md#t38)

<a id="a58"></a>
## A58: Increase commitment

**Failure or backfire route:** Persistence locks resources into an obsolete goal.

**Intended beneficial effect:** A chosen commitment protects an endorsed goal while retaining justified exits.

**Ingredient evidence:** No source assigned; design inference.

<a id="a58a"></a>
### A58a: Protect a priority

**Use when:** Recurring competing demands displace a valued action.

1. Specify the protected action
2. Identify the competing demand
3. Reserve a feasible resource boundary
4. State which exceptional demands may override it.

**Redirect condition:** If the priority is no longer endorsed, revise rather than enforce it.

<a id="a58b"></a>
### A58b: Use a chosen constraint

**Use when:** The person wants help resisting a predictable temptation.

1. Identify the temptation and preferred alternative
2. Select a voluntary proportionate constraint
3. Check its foreseeable costs
4. Establish a practical exit for changed circumstances.

**Redirect condition:** If the constraint imposes disproportionate harm, choose environmental support instead.

<a id="a58c"></a>
### A58c: Commit to a decision rule

**Use when:** Repeated reconsideration is costly but blind persistence is risky.

1. State the present rationale
2. Specify continuation conditions
3. Define evidence that warrants exit
4. Follow the rule while its premises remain valid.

**Redirect condition:** If a premise changes outside the listed cases, reopen the rule.

**Linked target dimensions:** [T32: Priorities](../targets/motivation-and-value.md#t32), [T52: Balance of exploration and commitment](../targets/decision-processes.md#t52), [T56: Conditions that inhibit an action](../targets/action-control.md#t56), [T58: Persistence](../targets/action-control.md#t58), [T59: Conditions for changing course](../targets/action-control.md#t59)

<a id="a59"></a>
## A59: Specify a stopping rule

**Failure or backfire route:** A weak threshold ends inquiry before the decisive issue is settled.

**Intended beneficial effect:** Deliberation ends when further work is not justified by the remaining decision need.

**Ingredient evidence:** No source assigned; design inference.

<a id="a59a"></a>
### A59a: Stop after logical completion

**Use when:** A bounded question can be resolved from established premises.

1. Specify the required conclusion
2. Verify all necessary premises
3. Complete the valid inference
4. Stop once the question is answered at the required scope.

**Redirect condition:** If a premise is unsettled, report the conditional result instead of false completion.

<a id="a59b"></a>
### A59b: Stop when information cannot change the choice

**Use when:** Remaining uncertainty may be decision-irrelevant.

1. List feasible alternatives
2. Identify the uncertain facts
3. Vary those facts over plausible ranges
4. Stop inquiry if the same acceptable choice survives.

**Redirect condition:** If a plausible value reverses the choice, investigate that fact if worthwhile.

<a id="a59c"></a>
### A59c: Stop a failing route

**Use when:** Repeated effort has not produced the required progress.

1. Define a meaningful progress indicator in advance
2. Bound the resources justified by the goal
3. Inspect progress at the boundary
4. Switch route or retire the goal if the bound is exceeded.

**Redirect condition:** If progress is merely unobserved, distinguish that from demonstrated failure.

**Linked target dimensions:** [T6: Recognition of what is unknown](../targets/knowledge-and-uncertainty.md#t6), [T42: Tolerance of uncertainty](../targets/emotion-and-appraisal.md#t42), [T52: Balance of exploration and commitment](../targets/decision-processes.md#t52), [T53: Threshold for accepting an option](../targets/decision-processes.md#t53), [T54: Rule for stopping deliberation](../targets/decision-processes.md#t54), [T58: Persistence](../targets/action-control.md#t58)

## A60: Provide a tool

**Failure or backfire route:** The tool becomes a dependency the person cannot use or evaluate independently.

**Intended beneficial effect:** The tool improves the intended outcome, with dependence appropriate to the user's goal.

**Ingredient evidence:** [S21](../sources.md#s21)

<a id="a60a"></a>
### A60a: Externalize a difficult representation

**Use when:** Working memory or manual transformation is the obstacle.

1. Identify the operation to externalize
2. Choose a tool that performs it accurately
3. Supply verified inputs
4. Inspect the resulting representation at the point of use.

**Redirect condition:** If the tool hides a needed distinction, change the representation.

<a id="a60b"></a>
### A60b: Automate a reliable routine

**Use when:** A stable repeated operation consumes effort or is forgotten.

1. Specify its inputs and valid conditions
2. Verify the operation on a representative case
3. Attach it to the actual trigger
4. Retain a way to inspect and correct the result.

**Redirect condition:** If conditions vary materially, automate routing or reminders rather than judgment.

<a id="a60c"></a>
### A60c: Support learning without replacing it

**Use when:** Independent future competence is part of the goal.

1. Identify the operation the learner must acquire
2. Use the tool for hints or worked support
3. Transfer that operation back to the learner
4. Assess an unassisted new case.

**Redirect condition:** If only assisted performance improves, report useful assistance without claiming acquired skill.

**Linked target dimensions:** [T18: What stays available in the background](../targets/attention.md#t18), [T43: Estimate of one's competence](../targets/self-and-social-understanding.md#t43), [T65: Fluency of performance](../targets/memory-and-skill.md#t65)
