The adverse route is retained from the original catalog. Beneficial variants are candidate assemblies. Named central judgments still require evidence or an implemented operation; filling every field does not guarantee benefit.

<a id="a61"></a>
## A61: Demonstrate a solution

**Failure or backfire route:** Watching successfully is mistaken for being able to perform.

**Intended beneficial effect:** The learner can identify and subsequently perform the operation demonstrated.

**Ingredient evidence:** [S20](../sources.md#s20)

<a id="a61a"></a>
### A61a: Show a worked solution

**Use when:** The learner lacks the procedure for a well-specified task.

1. Select a representative problem
2. Show each consequential transformation and its reason
3. Mark the conditions authorizing each step
4. Give a nearby problem with less support.

**Redirect condition:** If a prerequisite is missing, explain that prerequisite before continuing.

<a id="a61b"></a>
### A61b: Contrast a correct and failed solution

**Use when:** A recurring mistake is hard to distinguish from correct work.

1. Hold the problem constant
2. Place correct and flawed solutions side by side
3. Identify their first consequential divergence
4. Derive the different outcomes from that divergence.

**Redirect condition:** If several features differ, simplify the pair before drawing a lesson.

<a id="a61c"></a>
### A61c: Make the next operation predictable

**Use when:** A learner can follow a demonstration but remains passive.

1. Show the state before a meaningful step
2. Invite a prediction when useful
3. Reveal the correct operation and reason
4. Transfer the next comparable step to the learner.

**Redirect condition:** If prediction becomes blind guessing, restore the missing explanation.

**Linked target dimensions:** [T64: Accuracy of a skill](../targets/memory-and-skill.md#t64)

<a id="a62"></a>
## A62: Ask for retrieval

**Failure or backfire route:** An impossible recall demand teaches discouragement or rehearses an error.

**Intended beneficial effect:** Relevant information or a procedure can be recovered without the original answer in view.

**Ingredient evidence:** [S1](../sources.md#s1)

<a id="a62a"></a>
### A62a: Retrieve without the answer

**Use when:** The material has been understood but may not be accessible later.

1. Hide the original answer
2. Use a cue matching the intended use
3. Retrieve the answer
4. Compare with the source and correct omissions.

**Redirect condition:** If retrieval repeatedly fails, restore instruction before another attempt.

<a id="a62b"></a>
### A62b: Use decreasing cues

**Use when:** Unaided recall is currently too difficult.

1. Start with the smallest useful cue
2. Recover the missing content
3. Remove part of the cue on the next suitable occasion
4. Continue toward the intended support level.

**Redirect condition:** If cues simply reveal the answer, redesign them to require the target operation.

<a id="a62c"></a>
### A62c: Retrieve through application

**Use when:** The goal is usable knowledge rather than verbal repetition.

1. Present a fresh problem requiring the rule
2. Withhold the rule's name
3. Apply the recalled rule
4. Compare both rule selection and execution with the specification.

**Redirect condition:** If the rule is known but not selected, practice recognition of its use conditions.

**Linked target dimensions:** [T61: Accessibility of known information](../targets/memory-and-skill.md#t61), [T62: Retention over time](../targets/memory-and-skill.md#t62)

<a id="a63"></a>
## A63: Space revisits

**Failure or backfire route:** The interval exceeds what can be recovered with the available support.

**Intended beneficial effect:** Knowledge remains accessible across the delay relevant to its intended use.

**Ingredient evidence:** [S1](../sources.md#s1), [S13](../sources.md#s13)

<a id="a63a"></a>
### A63a: Space according to recoverability

**Use when:** Repeated use over time is required.

1. Establish an initially correct representation
2. Revisit after a delay
3. Attempt retrieval before reopening the answer
4. Lengthen or shorten the next interval according to recovery.

**Redirect condition:** If the interval exceeds current recoverability, add support rather than repeating failure.

<a id="a63b"></a>
### A63b: Interleave confusable cases

**Use when:** The task requires choosing among similar categories or methods.

1. Select contrasting categories
2. Alternate representative examples
3. Require choosing the category or method
4. Explain the feature that distinguishes each case.

**Redirect condition:** If the learner lacks any category model, provide initial examples first.

<a id="a63c"></a>
### A63c: Revisit at actual use points

**Use when:** A rule is repeatedly needed in a recurring workflow.

1. Identify the recurring use occasion
2. Place a retrieval cue there
3. Recover and apply the rule
4. Correct it from a reliable reference when needed.

**Redirect condition:** If use is too rare for retention, preserve a dependable external reference.

**Linked target dimensions:** [T20: Categories](../targets/representation.md#t20), [T60: Degree of automaticity](../targets/action-control.md#t60), [T62: Retention over time](../targets/memory-and-skill.md#t62)

<a id="a64"></a>
## A64: Vary the context

**Failure or backfire route:** Too much variation prevents the common structure from becoming apparent.

**Intended beneficial effect:** The learner recognizes what transfers and adapts what changes in a new setting.

**Ingredient evidence:** [S12](../sources.md#s12), [S13](../sources.md#s13)

<a id="a64a"></a>
### A64a: Vary one feature

**Use when:** A rule is tied too narrowly to one example.

1. Keep the governing relation fixed
2. Change one surface or contextual feature
3. Apply the rule
4. State why the changed feature does not alter its validity.

**Redirect condition:** If validity changes, teach the boundary instead of claiming transfer.

<a id="a64b"></a>
### A64b: Expose an invariant

**Use when:** Several diverse cases share a useful structure.

1. Align the cases by functional roles
2. Identify the preserved relation
3. Express it without case-specific vocabulary
4. Solve another structurally matching case.

**Redirect condition:** If no invariant is supported, retain separate rules.

<a id="a64c"></a>
### A64c: Practice adaptation

**Use when:** A new case preserves some structure but changes a consequential condition.

1. Identify the shared part
2. Locate the changed condition
3. Modify the affected operation
4. Verify the adapted result against the new requirements.

**Redirect condition:** If the change invalidates the method, select another method.

**Linked target dimensions:** [T23: Connections among ideas](../targets/representation.md#t23), [T66: Transfer to unfamiliar cases](../targets/memory-and-skill.md#t66)

<a id="a65"></a>
## A65: Compare near-matches

**Failure or backfire route:** Surface similarities become the rule for classification.

**Intended beneficial effect:** A previously confused distinction guides correct classification or action.

**Ingredient evidence:** [S12](../sources.md#s12), [S13](../sources.md#s13)

<a id="a65a"></a>
### A65a: Construct a minimal pair

**Use when:** One feature determines the distinction.

1. Choose two cases differing in that feature
2. Hold irrelevant details constant
3. Derive the different classification or action
4. State the discriminating rule.

**Redirect condition:** If outcomes do not differ, the chosen feature does not establish this boundary.

<a id="a65b"></a>
### A65b: Locate a boundary

**Use when:** The category changes across a continuous dimension.

1. Select cases on both sides
2. Move toward the transition
3. Identify the rule or uncertainty governing borderline cases
4. Apply it to an unseen boundary case.

**Redirect condition:** If the boundary is conventional, explain the convention rather than implying a natural divide.

<a id="a65c"></a>
### A65c: Defeat a misleading resemblance

**Use when:** Surface similarity invites the wrong rule.

1. Pair a misleading look-alike with a structural match
2. Map the causal or logical roles
3. Choose the case sharing the governing relation
4. Explain why appearance is insufficient.

**Redirect condition:** If structural similarity is also uncertain, qualify the comparison.

**Linked target dimensions:** [T13: What gets noticed](../targets/attention.md#t13), [T19: Distinctions](../targets/representation.md#t19), [T20: Categories](../targets/representation.md#t20), [T21: Boundaries](../targets/representation.md#t21), [T66: Transfer to unfamiliar cases](../targets/memory-and-skill.md#t66)

<a id="a66"></a>
## A66: Give feedback

**Failure or backfire route:** Vague or delayed judgment produces self-blame without a repair.

**Intended beneficial effect:** Feedback changes the operation responsible for an error or supports a demonstrable improvement.

**Ingredient evidence:** No source assigned; design inference.

<a id="a66a"></a>
### A66a: Repair the controlling error

**Use when:** A result contains several downstream mistakes.

1. Compare the work with the required result
2. Locate the earliest consequential error
3. Explain the correct operation at that point
4. Propagate the repair through dependent steps.

**Redirect condition:** If the specification is ambiguous, resolve it before marking the work wrong.

<a id="a66b"></a>
### A66b: Connect action to consequence

**Use when:** The person sees an outcome but not which action produced it.

1. Identify the observed action
2. Trace its supported consequence
3. Contrast a feasible alternative
4. State the operation to retain or change next time.

**Redirect condition:** If causation is unresolved, present the alternative as a hypothesis.

<a id="a66c"></a>
### A66c: Extract a recurring pattern

**Use when:** Several comparable attempts reveal systematic difficulty.

1. Group errors by operation
2. Find the most consequential recurring pattern
3. Address its common cause
4. Inspect a new instance after the repair.

**Redirect condition:** If cases have different causes, avoid a single generic correction.

**Linked target dimensions:** [T64: Accuracy of a skill](../targets/memory-and-skill.md#t64), [T68: Recognition of an error](../targets/self-correction.md#t68)

<a id="a67"></a>
## A67: Request an attempt before explanation

**Failure or backfire route:** An unsupported attempt rehearses an error without resolving it.

**Intended beneficial effect:** An initial attempt exposes a useful expectation or missing operation without unnecessary failure.

**Ingredient evidence:** [S7](../sources.md#s7)

<a id="a67a"></a>
### A67a: Commit an expectation

**Use when:** A later result will be informative only relative to a prior belief.

1. Define the outcome
2. Record a brief prediction and reason
3. Present the relevant evidence
4. Compare the difference and revise the controlling premise.

**Redirect condition:** If the person already knows the result, use a genuinely unresolved case.

<a id="a67b"></a>
### A67b: Complete a partial solution

**Use when:** The learner can perform part of the task.

1. Supply established prerequisites
2. Leave one meaningful operation unfinished
3. Let the learner complete it
4. Explain the result before increasing independence.

**Redirect condition:** If completion requires unknown material, teach that material first.

<a id="a67c"></a>
### A67c: Locate an understanding gap

**Use when:** Fluent endorsement may conceal a missing causal step.

1. Choose one claimed mechanism
2. Request its intermediate operations
3. Locate the first unexplained transition
4. Provide the missing explanation or qualify the original claim.

**Redirect condition:** If detailed explanation is irrelevant to the task, avoid this burden.

<a id="a68"></a>
## A68: Ask the person to advise or teach

**Failure or backfire route:** A poorly grounded explanation becomes more rehearsed and persuasive.

**Intended beneficial effect:** Teaching or advising improves accurate, applicable understanding or the person's own action.

**Ingredient evidence:** [S5](../sources.md#s5)

<a id="a68a"></a>
### A68a: Give verified advice

**Use when:** The person has relevant experience another case can use.

1. Choose a concrete recipient situation
2. Formulate advice tied to its constraints
3. Check the advice against a reliable standard
4. Identify the principle the adviser can reuse.

**Redirect condition:** If the advice is inaccurate, correct it before reinforcing confidence.

<a id="a68b"></a>
### A68b: Teach to expose one gap

**Use when:** Explaining a topic could reveal an unresolved dependency.

1. Select a narrow concept
2. Explain how it produces an outcome
3. Locate an unsupported or skipped step
4. Repair that step from evidence or a worked example.

**Redirect condition:** If explanation is already complete, move to application rather than repeated teaching.

<a id="a68c"></a>
### A68c: Apply one's own advice

**Use when:** Sound advice is not being used by its author.

1. State the advice already given
2. Compare the two situations and constraints
3. Identify the transferable operation
4. Adapt it into the adviser's actual next action.

**Redirect condition:** If circumstances differ materially, change the advice rather than accuse inconsistency.

<a id="a69"></a>
## A69: Provide scaffolding

**Failure or backfire route:** Support never withdraws and independent ability never develops.

**Intended beneficial effect:** Support enables progress and, where intended, decreases as independent competence develops.

**Ingredient evidence:** [S20](../sources.md#s20), [S21](../sources.md#s21)

<a id="a69a"></a>
### A69a: Fade worked steps

**Use when:** A novice is learning a specified procedure.

1. Provide a correct worked example
2. Remove one understood step in a similar problem
3. Have the learner supply it
4. Remove further support as performance permits.

**Redirect condition:** If errors expose a missing prerequisite, restore support at that point.

<a id="a69b"></a>
### A69b: Transfer an external operation inward

**Use when:** A representation supports a skill the person wants independently.

1. Use the representation to expose the operation
2. Name the relation it makes visible
3. Perform that operation with less external support
4. Assess a comparable unsupported case.

**Redirect condition:** If permanent support better serves the goal, retain it without calling it independent mastery.

<a id="a69c"></a>
### A69c: Give the minimum useful hint

**Use when:** The learner is stuck at a specific point.

1. Identify the last correct state
2. Name the relevant principle without the answer
3. Let the learner perform the next operation
4. Add a more explicit cue only if necessary.

**Redirect condition:** If the principle is unknown, give instruction instead of cryptic hints.

**Linked target dimensions:** [T65: Fluency of performance](../targets/memory-and-skill.md#t65)

<a id="a70"></a>
## A70: Create a memory cue

**Failure or backfire route:** The slogan is remembered while its qualifications disappear.

**Intended beneficial effect:** A recognizable cue recovers the correct content, including its important limits.

**Ingredient evidence:** [S1](../sources.md#s1)

<a id="a70a"></a>
### A70a: Bind recall to an event

**Use when:** The rule is forgotten at a recurring use point.

1. Identify the event that precedes use
2. Choose a cue present at that event
3. Attach the accurate rule
4. Apply it on the next relevant occasion.

**Redirect condition:** If the event is unreliable, use another cue or external reminder.

<a id="a70b"></a>
### A70b: Encode a contrast

**Use when:** Two similar items are repeatedly confused.

1. Identify their discriminating feature
2. Build a short cue around that feature
3. Retrieve both items from it
4. Apply the distinction to a new example.

**Redirect condition:** If the cue preserves sound but loses meaning, replace it.

<a id="a70c"></a>
### A70c: Keep the qualification attached

**Use when:** A memorable claim could outlive its limiting condition.

1. Name the material qualification
2. Incorporate it into the same retrievable phrase or representation
3. Use the combined form consistently
4. Inspect recall of the condition as well as the claim.

**Redirect condition:** If accurate compression is impossible, use a brief linked reference.

**Linked target dimensions:** [T13: What gets noticed](../targets/attention.md#t13), [T18: What stays available in the background](../targets/attention.md#t18), [T61: Accessibility of known information](../targets/memory-and-skill.md#t61), [T63: Associations that cue recall](../targets/memory-and-skill.md#t63)
