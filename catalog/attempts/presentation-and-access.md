# Presentation and access

[All targets and attempts](../contents.md) · [Completed finite recipes](../worked-recipes.md)

The adverse route is retained from the original catalog. Beneficial variants are candidate assemblies. Named central judgments still require evidence or an implemented operation; filling every field does not guarantee benefit.

<a id="a1"></a>
## A1: Repeat something familiar

**Failure or backfire route:** Boredom or irritation makes the person disengage from relevant later material.

**Intended beneficial effect:** The familiar material produces a new usable inference, warranted confidence revision, or successful use.

**Ingredient evidence:** No source assigned; design inference.

<a id="a1a"></a>
### A1a: Derive an unused consequence

**Use when:** A proposition is already accepted but a relevant implication is unused.

1. Write the accepted proposition
2. Attach one presently relevant condition
3. Derive the consequence without restating background
4. Apply that consequence to the live question.

**Redirect condition:** If the consequence is already available, select a different unresolved dependency rather than rewording it.

<a id="a1b"></a>
### A1b: Recalibrate justified confidence

**Use when:** The claim is known but its evidential strength is misunderstood.

1. Identify the claimed confidence and reason
2. Add independent confirming or limiting evidence
3. Revise the supported range
4. State which choice the revision affects.

**Redirect condition:** If no new evidential distinction exists, omit the repetition.

<a id="a1c"></a>
### A1c: Recover knowledge at the moment of use

**Use when:** The person knows the rule but fails to retrieve it in a relevant situation.

1. Identify the recognizable use condition
2. Pair it with a short accurate cue
3. Apply the rule to the current case
4. Preserve the exception with the cue.

**Redirect condition:** If the rule is retrieved but still unused, diagnose relevance or action constraints rather than memory.

<a id="a2"></a>
## A2: Choose a topic

**Failure or backfire route:** A relevant-sounding tangent displaces the issue that actually matters.

**Intended beneficial effect:** The selected issue has a defensible route to a valuable change in the present situation.

**Ingredient evidence:** No source assigned; design inference.

<a id="a2a"></a>
### A2a: Find the blocking dependency

**Use when:** Progress is blocked despite substantial available knowledge.

1. Name the desired next transition
2. List its necessary prerequisites
3. Identify the first missing prerequisite from available evidence
4. Address that prerequisite before neighboring topics.

**Redirect condition:** If no prerequisite is missing, examine the value of the selected transition.

<a id="a2b"></a>
### A2b: Resolve decision-sensitive uncertainty

**Use when:** A real choice depends on something unsettled.

1. List feasible choices
2. Name the facts that could reverse their ordering
3. Separate obtainable from unavailable facts
4. Address the cheapest consequential uncertainty.

**Redirect condition:** If no uncertainty changes the choice, help implement or revisit the objective.

<a id="a2c"></a>
### A2c: Correct a mistaken question

**Use when:** The literal question presupposes a disputed condition.

1. Write the presupposition and its consequence
2. Check whether it holds
3. Reformulate the question with the corrected condition
4. Carry through the implication for the user's original concern.

**Redirect condition:** If the presupposition is sound, retain the original question.

**Linked target dimensions:** [T6: Recognition of what is unknown](../targets/knowledge-and-uncertainty.md#t6), [T29: Directions searched](../targets/possibilities.md#t29)

<a id="a3"></a>
## A3: Open with background

**Failure or backfire route:** The person leaves before encountering the decisive material.

**Intended beneficial effect:** The recipient reaches the decisive point with the prerequisites needed to interpret it.

**Ingredient evidence:** No source assigned; design inference.

<a id="a3a"></a>
### A3a: Insert one prerequisite

**Use when:** One missing concept prevents the main inference.

1. Write the main conclusion
2. Identify the one term or relation it depends on
3. Supply a minimal example of that prerequisite
4. Immediately use it in the main inference.

**Redirect condition:** If several prerequisites are missing, order them by dependency and provide a short route through them.

<a id="a3b"></a>
### A3b: Start at the expert's unresolved edge

**Use when:** Existing context shows that basic background is already understood.

1. List the established starting facts privately
2. Delete explanations of them
3. Introduce the first unresolved relation
4. Expand only the part that cannot be inferred from the established facts.

**Redirect condition:** If prior knowledge is uncertain and changes the route, resolve that specific uncertainty.

<a id="a3c"></a>
### A3c: State the disputed premise first

**Use when:** Background itself contains the contested assumption.

1. Name the disputed premise
2. Distinguish conditional reasoning from endorsement
3. Show what follows if it holds and if it fails
4. Pursue the branch supported by available evidence.

**Redirect condition:** If neither branch can be selected, preserve the conditional result.

<a id="a4"></a>
## A4: Compress an explanation

**Failure or backfire route:** A missing qualification produces a confident misunderstanding.

**Intended beneficial effect:** The shorter representation preserves the inferences, qualifications, and actions needed for the task.

**Ingredient evidence:** No source assigned; design inference.

<a id="a4a"></a>
### A4a: Remove inferential duplicates

**Use when:** Several passages do the same work.

1. Assign each passage its distinct contribution
2. Merge passages with the same contribution
3. Retain one concrete demonstration
4. Check that the conclusion still follows.

**Redirect condition:** If deleting a passage breaks an inference, restore the missing relationship in fewer words.

<a id="a4b"></a>
### A4b: Replace prose with a relation

**Use when:** A verbal sequence hides a simple comparison or dependency.

1. Extract the entities and relationship
2. Choose a table, equation, or short ordered sequence
3. Encode every consequential condition
4. Apply the representation to one relevant case.

**Redirect condition:** If symbols require more explanation than the original, keep the clearer prose.

<a id="a4c"></a>
### A4c: Separate the usable core from detail

**Use when:** Different readers need different levels of support.

1. Write the conclusion with its scope
2. Place the minimum supporting reason beside it
3. Move optional evidence beneath it
4. Label what extra question each optional detail resolves.

**Redirect condition:** If the core invites a foreseeable misreading, move its missing qualification into the core.

**Linked target dimensions:** [T22: Level of detail](../targets/representation.md#t22)

<a id="a5"></a>
## A5: Add detail

**Failure or backfire route:** Processing demands exceed what the person can use.

**Intended beneficial effect:** The added detail repairs a named gap without introducing avoidable cognitive work.

**Ingredient evidence:** No source assigned; design inference.

<a id="a5a"></a>
### A5a: Repair a missing inference

**Use when:** The recipient can follow everything except one transition.

1. Locate the last understood step and first unsupported step
2. Expose the operation connecting them
3. Work it on the actual case
4. Return to the main argument.

**Redirect condition:** If the operation requires another prerequisite, teach that prerequisite before repeating the step.

<a id="a5b"></a>
### A5b: Expose a boundary

**Use when:** A statement is being applied too broadly.

1. State the rule's conditions
2. Show a matching and a near-matching nonmatching case
3. Identify the condition that changes the result
4. Restate the bounded rule.

**Redirect condition:** If the cases differ in several consequential ways, construct a cleaner pair.

<a id="a5c"></a>
### A5c: Add decision-relevant precision

**Use when:** A vague quantity or condition changes what should be done.

1. Identify the threshold separating actions
2. Refine only the quantities that could cross it
3. Show the remaining uncertainty
4. Select the action robust to that uncertainty.

**Redirect condition:** If precision cannot affect the action, omit it.

**Linked target dimensions:** [T21: Boundaries](../targets/representation.md#t21), [T22: Level of detail](../targets/representation.md#t22)

<a id="a6"></a>
## A6: Use a vivid example

**Failure or backfire route:** An exceptional case distorts judgments of what is typical.

**Intended beneficial effect:** The example changes the intended distinction without supporting a false generalization.

**Ingredient evidence:** No source assigned; design inference.

<a id="a6a"></a>
### A6a: Construct a minimal pair

**Use when:** Two conditions are repeatedly confused.

1. Choose two cases identical on irrelevant features
2. Vary the decisive feature
3. Derive the different outcomes
4. State exactly which distinction the pair establishes.

**Redirect condition:** If the causal difference is ambiguous, simplify the pair further.

<a id="a6b"></a>
### A6b: Use a representative case with context

**Use when:** The recipient needs a concrete sense of an ordinary process.

1. Choose a case justified as relevant to the target population
2. Show the process step by step
3. Provide the frequency or range needed to interpret it
4. Separate illustration from prevalence evidence.

**Redirect condition:** If representativeness is unknown, label the case illustrative and avoid frequency conclusions.

<a id="a6c"></a>
### A6c: Use an existence counterexample

**Use when:** An absolute impossibility or universal claim blocks thought.

1. Quote the exact universal claim
2. Verify a case satisfying its premises
3. Show the conflicting outcome
4. Revise only the defeated quantifier or condition.

**Redirect condition:** If the case violates a premise, it is not a valid counterexample; replace it.

**Linked target dimensions:** [T19: Distinctions](../targets/representation.md#t19)

<a id="a7"></a>
## A7: Use an analogy

**Failure or backfire route:** The person transfers a feature that the two situations do not share.

**Intended beneficial effect:** The recipient can transfer the intended relationship and reject a tempting invalid transfer.

**Ingredient evidence:** [S12](../sources.md#s12)

<a id="a7a"></a>
### A7a: Map relationships explicitly

**Use when:** A familiar domain has the relevant structure.

1. Write the target relationship
2. Choose a familiar case with the same relationship
3. Map roles and causal links
4. Identify one salient feature that does not transfer.

**Redirect condition:** If only superficial resemblance survives, discard the analogy.

<a id="a7b"></a>
### A7b: Compare two source cases

**Use when:** A general structure must transfer beyond one memorable example.

1. Present two cases sharing the target relationship
2. Align corresponding roles
3. Extract the common relation
4. Apply it to a third case with different surface features.

**Redirect condition:** If transfer follows surface words, use a third case where those words mislead.

<a id="a7c"></a>
### A7c: Use an analogy to reveal its limit

**Use when:** An existing analogy is distorting interpretation.

1. Write the inference imported from the analogy
2. Identify the structural requirement for that inference
3. Show that requirement is absent in the target
4. Replace the imported conclusion with a target-specific account.

**Redirect condition:** If the requirement actually holds, retain the valid portion of the analogy.

**Linked target dimensions:** [T23: Connections among ideas](../targets/representation.md#t23)

<a id="a8"></a>
## A8: Introduce a name

**Failure or backfire route:** Recognizing the label is mistaken for understanding the phenomenon.

**Intended beneficial effect:** The label enables accurate recognition or action that was previously difficult.

**Ingredient evidence:** No source assigned; design inference.

<a id="a8a"></a>
### A8a: Name a recurring distinction

**Use when:** A useful difference is repeatedly rediscovered.

1. Show a positive case and a near-miss
2. State the difference in ordinary words
3. Assign the shortest unambiguous name
4. Use it in a fresh instance.

**Redirect condition:** If the difference cannot be stated, postpone naming.

<a id="a8b"></a>
### A8b: Split an overloaded term

**Use when:** One word refers to several consequentially different things.

1. List its meanings in the live conversation
2. Assign separate literal phrases
3. Substitute them into the disputed claims
4. Identify which disagreement survives.

**Redirect condition:** If no consequence changes, keep the ordinary term.

<a id="a8c"></a>
### A8c: Replace an abstract label with an operation

**Use when:** A noun conceals what is supposed to happen.

1. Identify the actor, input, operation, and changed state
2. Write the literal action
3. Demonstrate it once
4. Retain a short label only as an index to that action.

**Redirect condition:** If the operation is unspecified, mark the entry incomplete rather than inventing apparent precision.

**Linked target dimensions:** [T19: Distinctions](../targets/representation.md#t19)

<a id="a9"></a>
## A9: Offer a large catalog

**Failure or backfire route:** The volume obscures which entry would help now.

**Intended beneficial effect:** The catalog leads to a suitable entry while preserving access to relevant alternatives.

**Ingredient evidence:** No source assigned; design inference.

<a id="a9a"></a>
### A9a: Route by the present obstruction

**Use when:** The user needs help now from a large collection.

1. Describe the current obstruction in observable terms
2. Choose the first discriminating routing question from existing context
3. Show the few matching entries
4. Expose why each is applicable.

**Redirect condition:** If routing depends on an unknown fact, ask only that fact or preserve both branches.

<a id="a9b"></a>
### A9b: Order by prerequisites

**Use when:** Entries depend on one another.

1. Record each entry's required starting knowledge or capability
2. Construct the dependency order
3. Place the first missing prerequisite at the entry point
4. Make later entries accessible when it is acquired.

**Redirect condition:** If the dependency is merely customary, remove it.

<a id="a9c"></a>
### A9c: Index by the change enabled

**Use when:** Subject labels do not reveal usefulness.

1. For each entry name its before-and-after change
2. Group entries that enable comparable transitions
3. Distinguish variants by starting conditions
4. Provide a direct path from the user's situation to those conditions.

**Redirect condition:** If an entry has no identifiable change it enables, move it to background reference.

<a id="a10"></a>
## A10: Draw a diagram

**Failure or backfire route:** A tidy picture makes an unsupported relationship appear established.

**Intended beneficial effect:** The visual representation supports the intended inference without invented relationships.

**Ingredient evidence:** No source assigned; design inference.

<a id="a10a"></a>
### A10a: Draw a dependency structure

**Use when:** The obstacle is understanding what depends on what.

1. List entities and verified relations
2. Label each link with its literal meaning
3. Mark unknown links explicitly
4. Trace the path relevant to the current question.

**Redirect condition:** If the diagram adds unsupported causal arrows, replace them with the actual relation.

<a id="a10b"></a>
### A10b: Draw a decision fork

**Use when:** The obstacle is selecting among conditional actions.

1. List available actions
2. Identify the facts that distinguish their applicability
3. Order those conditions into branches
4. Walk one ordinary and one boundary case through the diagram.

**Redirect condition:** If branches omit a feasible case, add an explicit unresolved branch.

<a id="a10c"></a>
### A10c: Draw change over time

**Use when:** Event order or delay controls interpretation.

1. List dated or ordered events
2. Separate observation from hypothesized causation
3. Represent delays and feedback explicitly
4. Use the picture to answer the temporal question.

**Redirect condition:** If time is unknown, show partial order rather than fabricated spacing.
