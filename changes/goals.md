# Goals

## Method requirements

A condition required by one method becomes a requirement of the goal only if every adequate route requires it.

1. State the desired condition separately from the proposed means.
2. Attach each alleged prerequisite to the operation that requires it.
3. Construct a route to the same desired condition that omits that operation.
4. Check whether the new route preserves the desired condition and actual constraints; if it does, the omitted prerequisite belonged to the method.

The previous index required extracting an archive to reach 36 linked records. Extraction was a prerequisite of that storage arrangement, not of understanding those records. Exposing the needed records directly removes that prerequisite while preserving their bytes.

The missing-link count is an observed property of the repository snapshot. The new exposed paths are checked by repository validation; no reading-time or recipient effect is inferred.

## Success criteria

A procedure can satisfy its recorded target while failing the concern that made the target worthwhile.

1. Construct the state in which the stated completion criterion is satisfied exactly.
2. Identify what the original concern still requires in that state.
3. If a requirement remains unmet, separate completion of the current procedure from adequacy of the goal or criterion.
4. Revise the criterion explicitly before comparing new attempts; retain the earlier result under the criterion that actually governed it.

A transition record can contain every required field while 'diagnose the locus' and 'choose a mechanism' remain unimplemented. Record completeness therefore cannot certify an executable recipe. Likewise, 3,000 ranked statements cannot certify 3,000 effective methods.

Both mismatches are directly inspectable in the repository and this conversation's artifacts. Their correction does not establish a universal replacement recipe.
