# Memory

## Conditional indexing

Stored information remains unusable when the encountered condition does not lead to its retrieval. An index changes access while leaving the underlying information intact.

1. Preserve each original record, including its trigger, action, exception, result, and provenance.
2. Index the literal trigger to the original record rather than replacing the record with its summary.
3. Retrieve the exception together with the ordinary action.
4. Compare retrieved fields with the canonical record and retain multiple matches as a collision requiring resolution.

The existing eight-row register preserves 48 fields. 'Checksum mismatch after deployment' retrieves the condition 'schema version advanced' and the action 'rebuild the read index before rollback.' An index returning only 'rollback' has discarded the decisive condition.

The source records demonstrate immediate artifact retrieval. Spaced retrieval, durable memory, paraphrase robustness, and broader policy transfer remain separate questions.

## Conditional transfer

A remembered action can transfer while its justification does not. The retained condition determines whether reuse is warranted.

1. Recover the original condition, action, exception, and policy scope.
2. Match the new case to the condition rather than to the old actor's name or superficial appearance.
3. Identify any changed authority, policy, or dependency that could defeat the match.
4. Reuse the action only within the surviving scope; otherwise retain the old case as a candidate rather than an instruction.

Changing the analyst's name to Dana leaves the stored checksum condition unchanged. It does not establish that Dana's organization authorizes the same rollback policy. The source's constructed transfer works within its stipulated policy, not every organization.

A single constructed transfer is recorded; universal applicability is not.
