# Step 4: Formalize into explicit steps

FORMALIZED PROCEDURE:

Step 1: Fix the terminal condition.
  - Input: request, beneficiary, current state, prohibited outcomes, evidence horizon.
  - Decision criteria: the condition must be observable in the relevant artifact, action, environment, or reported human state; preserve multiple conditions when they are not interchangeable.
  - Output: a set of checkable terminal conditions and unresolved human conditions.

Step 2: Generate materially different transition candidates.
  - Input: terminal conditions.
  - Decision criteria: include every plausible controlling locus among environment/time/location, tool/coordination, available action, representation/perception, attention/memory cue, belief, motivation/appraisal/emotion, plus “remain unresolved.” Do not create a locus with no causal path to the condition.
  - Output: candidate transition, actor, locus, and resulting state.

Step 3: Write each candidate's causal chain.
  - Input: candidate transition and present evidence.
  - Decision criteria: mark every necessary intermediate state, every unobserved human transition, every factual premise, and every external dependency. A desired human effect is unresolved until observed.
  - Output: supported links, unsupported links, and exact gates.

Step 4: Apply benefit and authority gates.
  - Input: causal chains, declared values, severe-harm exclusions, permissions, and affected parties.
  - Decision criteria: reject candidates that reach the literal condition by violating the beneficiary's controlling values, exceeding authority, discarding provenance, removing necessary choice, or crossing a severe-harm boundary.
  - Output: eligible candidates plus explicit rejections.

Step 5: Compare only candidates that reach the same terminal condition.
  - Input: eligible candidates.
  - Decision criteria: candidate A dominates B only if A is no worse in evidential support, authorization, severe-harm exposure, reversibility, and number of unsupported intermediate links, and is strictly better on at least one. Word count alone does not establish efficiency.
  - Output: non-dominated candidates; select one only when the declared priorities order them.

Step 6: Activate reasoning where a candidate remains underspecified.
  - Input: non-dominated candidates and unresolved nodes.
  - Decision criteria: select original procedures for the exact unresolved search, derivation, distinction, value conflict, evidence question, or safety boundary. Preserve their source and execution requirements. Do not execute a procedure merely to make the record look rigorous.
  - Output: resolved candidate or an honest unresolved branch.

Step 7: Emit the smallest sufficient intervention and a result check.
  - Input: selected candidate and terminal condition.
  - Decision criteria: include what changes, who or what changes it, necessary exception/provenance, and the observable check. Exclude method narration that does not affect execution.
  - Output: response plus result condition, scope, and unresolved human effects.

DECISION TREE:

- If a safe, authorized tool or environment change directly establishes a machine-checkable terminal condition → select it over a route dependent only on repeated human recall.
- If information arrangement blocks the valid choice but does not require a new fact → change representation or attention.
- If a disputed fact controls the choice → perform the necessary evidence or reasoning operation before selecting the downstream transition.
- If the target is an observed human belief, appraisal, motivation, emotion, or memory state → select an intervention only with a stated observation and retain uptake as unresolved until measured.
- If candidates reach different terminal conditions or values do not order them → retain the non-dominated set or request the missing priority; do not manufacture one optimum.
- If every direct candidate is unauthorized or crosses a harm boundary → preserve the unresolved condition.

QUALITY CHECKS:

- Check: Does the response name an observable terminal condition? Good: “`r3` remains non-complete while evidence is absent.” Bad: “Improve coordination.”
- Check: Does the chosen locus control the condition? Good: merge validation rejects an incompatible criterion version. Bad: a paragraph asks future memory to catch every mismatch.
- Check: Are human effects reported only when observed? Good: “message content changed; contributor response unknown.” Bad: “the message reduced anxiety.”
- Check: Are benefit and efficiency separate? Good: directness loses to safety or authority. Bad: shortest response wins automatically.
- Check: Is a reasoning procedure tied to a live unresolved node? Good: verify the criterion-version relation. Bad: run another skill because the program rewards output.
