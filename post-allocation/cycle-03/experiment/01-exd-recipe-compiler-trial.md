# EXD — prospective recipe-compiler trial

Intended mind change: Replace confidence from constructed cases with a prospective comparison capable of detecting whether the recipe compiler improves real recipient changes.

Actual starting judgment: Reuse across frozen cases made the compiler look promising enough to call beneficial.

Concrete input: compare the typed recipe compiler with the strongest current skill-first process on genuinely new prompts and recipients; no participants, effect-size estimate, or outcomes are supplied.

## Hypotheses and predictions

H1: On new eligible cases, compiler-guided attempts produce a higher rate of preregistered target-state attainment without adverse or unauthorized change than skill-first attempts.

H0: There is no difference between conditions on that rate.

Mechanism prediction: the compiler reduces wrong-locus attempts by requiring admissibility, locus, operator, and witness selection before mechanism selection. Falsifiers: no difference; more adverse/unauthorized transitions; or improvement entirely explained by longer preparation time.

No magnitude is predicted because no pilot or prior effect estimate exists. Any numeric superiority threshold added after outcomes would be retrospective.

## Variables

- IV: process condition. Compiler = `admissibility → locus → typed variable/criterion → operator/invariant → mechanism/handoff → witness`; active control = strongest current skill-first process with equal tool access and time budget.
- Primary DV: case-level target attainment by the preregistered shape-specific witness, with zero overriding adverse/unauthorized transition for that case.
- Secondary DVs: wrong-locus attempt rate; time to executable attempt; recipient burden; number of unsupported completion claims; downstream action recorded separately.
- Manipulation check: artifacts must contain the compiler fields in compiler condition and source/skill selection before transition fields in control.
- Controls: same case pool, executor model/version, tool access, time budget, recipient channel, and evaluator rubric.
- Moderators: transition type, human versus nonhuman locus, authority availability, baseline agreement, and consequence level.
- Mediator candidate: correct controlling-locus diagnosis before first attempt.

## Design

Practical randomized blocked trial. Recruit new cases before outcomes are known. Block by transition type and authority gate; randomize within blocks to compiler or active control. A recipient sees only one condition for one case to avoid carryover. If the same executor handles both conditions, conceal the paired case identity and randomize order. Evaluators are blinded to condition labels; full artifact structure may make perfect blinding impossible and must be tested.

Eligibility: target state and success witness can be frozen; inputs are available; requested change is authorized and within risk policy. Exclude cases requiring unsafe action or an unavailable intervention. Gated physical/human operations may be included only if outcome observation is actually scheduled; otherwise they test handoff accuracy, not target attainment.

## Sample size and power

Required N is unresolved. There is no defensible expected effect size, baseline success rate, clustering estimate, or smallest effect worth adopting. First run a preregistered pilot whose purpose is to estimate rates, variance, missingness, and intraclass correlation—not to declare efficacy. Then set a smallest practically meaningful absolute improvement and calculate N at a prespecified alpha/power, adjusting for recipient/executor clustering and attrition. Do not substitute conventional effect sizes as facts.

## Validity controls

- Selection: consecutive eligible cases; report exclusions before assignment.
- History/distribution: concurrent control and timestamped case capture.
- Performance/time: equal budget; report actual time and tool calls.
- Expectancy: recipients do not receive condition labels; evaluators blinded where possible.
- Contamination: separate executor sessions and no cross-condition notes.
- Outcome flexibility: preregister the operator-specific witness and adverse-event veto for each case.
- Missing outcomes: retain unresolved cases; analyze bounds rather than treating missing as failure or success.
- Executor dependence: include multiple executors or treat executor as a random/blocking factor later.
- Novelty leakage: hash/freeze inputs before execution and check against prior examples.

## Analysis plan

Primary intention-to-treat comparison of admissible target-attainment proportions with confidence interval and clustered model if clustering exists. Report adverse/unauthorized changes separately; do not net them against benefits. Test wrong-locus rate as a mechanism outcome. Report time and recipient burden jointly rather than hiding increased cost. Multiplicity-adjust confirmatory secondary outcomes; label exploratory moderator/mediation results. Preserve all exclusions, missing outcomes, and protocol deviations.

Stopping: pause for a serious unauthorized or harmful transition. Do not stop early for favorable results without a prespecified sequential rule.

## Distinct later use

The design changes the current program claim: constructed reuse supports mechanism plausibility, not human efficacy. The index and prompt may adopt the compiler as the best supported working arrangement while explicitly leaving recipient benefit unresolved until this trial has data.

## Outcome

Actual mind change: I changed from “constructed reuse is enough to call the compiler beneficial” to a three-level claim: locally useful, prospectively testable, and human-beneficial only after observed outcomes.

Benefit or harm: The design blocks HARKing, wrong outcome witnesses, and missing-as-success. No experiment was run and no recipient changed.

Verdict: KEEP for a complete experimental design within scope; UNRESOLVED for efficacy.

Content assessment: Hypotheses, variables, design, randomization, controls, power prerequisites, validity threats, analysis, and stopping are explicit. Numeric N is correctly unavailable.

Organization assessment: Freeze case-specific transition witnesses before randomization; keep mechanism, benefit, harm, time, and authority outcomes separate.

Next attempts: Run an estimation pilot; define the smallest worthwhile improvement; recruit independent evaluators; measure rubric agreement; test executor-by-process interaction.
