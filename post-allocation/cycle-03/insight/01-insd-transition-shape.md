# INSD 8x — transition shape determines the success witness

Intended mind change: Replace one generic “changed/not changed” evaluation with success tests matched to the shape of the intended change.

Actual starting judgment: A before/after value comparison seemed sufficient across mind changes.

Concrete input: eight frozen cases B1–B8 in `frozen-inputs.md`.

## Phase and starting approach

Phase C from a partial insight, expanded through four discovery cycles. Current approach: compare one before-state with one after-state. Solved: each case gets a checkable success witness that neither invents change nor rejects a real non-scalar change.

## Twelve inversions

1. What if the stored value need not change? B4 adds an index while canonical memory is identical.
2. What if adding information is failure? B2 succeeds by excluding A and C from current attention.
3. What if removal is benefit? Noise inhibition can improve the selected signal.
4. What if equal before/after values hide changed access? B4 retrieval path changes.
5. What if a changed value hides unchanged capability? A new tool label without executable access is null.
6. What if capability changes without action? B5 enables an option that need not be taken.
7. What if action order changes while all actions remain? B6 is a permutation, not addition/removal.
8. What if a representation changes while propositions remain? B3 requires query preservation, not new beliefs.
9. What if location changes which distinctions are visible rather than where a body sits? B8 is a selection of representation locus.
10. What if value change is a constraint change rather than a scalar weight? B7 adds a privacy veto.
11. What if posterior direction is unknown until evaluation? B1 selects a variable/criterion before realizing `.10→4/13`.
12. What if “same output” conceals a different dependency graph? Equal text can be supported by different provenance.

The most uncomfortable inversion is 1: a mind can change usefully when its stored content does not change at all.

## Four representations

### R1 — scalar/vector delta

Represent each case as `after−before`. Works for B1 numeric posterior; fails to express B3 graph equivalence, B4 access path, B6 permutation meaning, and B7 veto semantics without arbitrary encoding.

### R2 — state-transition graph

Nodes are states; labeled edges are add, remove, substitute, reweight, reindex, enable, reorder, or relocate. This represents all eight, but “edge occurred” alone does not prove the intended invariant survived.

### R3 — operator plus invariant

`(locus, operator, precondition, preserved invariant, changed relation, postcondition)`. B3 becomes `(representation, substitute, same facts, preserve reachability, change distance visibility, graph answers query)`; B4 becomes `(memory access, reindex, canonical 48 fields, preserve content, change lookup path, one-access retrieval)`.

### R4 — verification signature

Each operator maps to evidence:

| Shape | Success witness |
|---|---|
| numeric update | value and derivation under fixed evidence |
| attention narrowing | designated item retained; excluded items absent from active set |
| representation substitution | required queries preserved; declared losses measured |
| reindexing | canonical content equal; retrieval path/cost changed |
| enablement | previously unreachable action becomes executable; action itself separately observed |
| reordering | same action multiset; dependency-valid permutation changed |
| constraint/value policy | previously admissible option becomes forbidden/conditional for stated value reason |
| relocation | query-relevant observable set changes at selected locus |

R4 changes evaluation operations directly and retains R3 as provenance.

## Four discovery cycles

Cycle 1: “use any before/after difference” fails B4 because storage is unchanged and fails B5 by conflating ability with action.

Cycle 2: grouping by changed object—belief, attention, representation, memory, tool, action, value, location—still permits the same object to change by addition, removal, reorder, or access-path change.

Cycle 3: grouping by operator shape produces distinct invariants and witnesses. Counterexample: two operators can share a witness type; representation substitution and relocation both require query tests.

Cycle 4: verification signatures organize by what must be observed, while operator and locus remain provenance fields. This survives overlap: one attempt can require several signatures rather than one forced class.

## Five crystal tests

1. B1 numeric update: supplied arithmetic verifies `.10→4/13`; a mere changed string fails.
2. B2 attention narrowing: active set `{A,B,C}→{B}` passes only if B remains and A/C are inactive; total information need not be deleted.
3. B3 representation: dependency graph passes a reachability query and must report any distance change; visual novelty alone fails.
4. B4 reindexing: canonical content remains 48/48 while changed-actor retrieval falls from up to eight inspections to one; a content delta test would falsely report no change.
5. B5 enablement: tool access changes an action from unreachable to reachable; no action receipt means “acted” remains false.

## Crystallization

Claim: A mind-change attempt’s success evidence is determined by its transition operator, locus, and preserved invariant; one generic before/after value test cannot distinguish reindexing, enablement, reordering, and representation-preserving changes.

Before: any visible pre/post difference could serve as success evidence.

Changes: select verification signature before executing; require content-equality plus access-change for reindexing; separate capability from action; test required queries and declared loss for representations; preserve action multiset for reorderings.

Strongest counterargument: every case can be represented as a predicate over one sufficiently rich global state, so one universal pre/post test is formally enough. Disposition: true at the meta-level but operationally empty—the predicate must still encode the operator-specific invariant and witness. The insight concerns executable tests, not mathematical representability.

Re-derivation is stored separately after a timed five-minute no-note interval in `insd-rederivation.md`.

## Distinct later use

Applied to B4, the generic content-delta test says “no change”; the reindexing signature says KEEP because 48/48 content is preserved and the query path changes from up to eight inspections to one. Applied to B5, the signature records capability KEEP but action UNRESOLVED. The evaluation verdicts therefore change without changing the cases.

## Outcome

Actual mind change: I changed from one delta test to a verification-signature system with operator, locus, precondition, invariant, changed relation, and postcondition.

Benefit or harm: The new system avoids one false negative on B4 and one false positive on B5, and it specifies different checks for all eight frozen cases.

Verdict: KEEP after successful five-minute no-note re-derivation; original 8x products include 12 inversions, four representations, four cycles, and five crystal tests. New finding: `transition-shape-determines-success-witness`.

Content assessment: All floors and countercase are explicit; independent human usefulness remains unobserved.

Organization assessment: Verification signature is the operational view; operator/locus/invariant tuple is the derivation view; object categories remain browse metadata.

Next attempts: Re-derive after a longer delay; test compound transitions; test harmful but technically successful transitions; compare independent evaluator agreement; measure evaluation time.
