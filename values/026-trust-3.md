# Trust design for disagreement that remains disagreement

Application: 026-trust-3. Actor: this assistant's current working model and generated artifacts unless a constructed case is explicitly identified. Human outcomes are not observed.

Starting working judgment: A shared statement of purpose seems a useful first trust structure, but it may conceal different assumptions about which disagreements will be tolerated.

Source: ../sources/values-trust.md. Requirements receipt: ../sources/values-trust.receipt.txt. Original loaded through read_original.py; byte checks are recorded separately in source-integrity.json.

Depth: Original 8x floors: 6+ party pairs, 3 dimensions plus structural and system analysis, 12 events, 10 interventions. Executed: six unordered pairs in both directions, twelve events, ten interventions, each with costs/prerequisites and a scoped signal assessment.

Interpretation: design. Entire social situation is constructed. Each fact below is stipulated; trust levels are conditional reliance assessments generated from those facts, not measurements of a human’s feelings. H/M/L/U mean high/medium/low/unknown within the stated task. No broad allegation of reciprocal blame is imported from the source. The corruption-pre-inoculation original was also loaded and retained.

Parties: A experimental artist; B archivist; C accessibility reviewer; D venue coordinator. They are planning a fictional exhibition that can change during visitors’ interaction.

Trust trajectory, twelve events:

|---|---|---|
| E1 | A proposes visitors rearrange objects. | Creative competence proposal, not tested |
| E2 | B states originals must remain traceable. | Explicit preservation criterion |
| E3 | C requests a non-visual route through the work. | Distinct access information |
| E4 | D states the room must close at a fixed time. | External operating constraint |
| E5 | A builds a reversible sample rearrangement. | One demonstrated prototype |
| E6 | B logs sample provenance. | One demonstrated archive operation |
| E7 | C identifies a visual-only instruction in the sample. | Specific review evidence |
| E8 | D provides an alternate access time for testing. | Concrete accommodation in case |
| E9 | A agrees to replicas for fragile originals. | Interest integration |
| E10 | B agrees that replica order can change. | Preservation not total stasis |
| E11 | C supplies a text-and-audio draft instruction. | Alternative representation |
| E12 | D declines an extension beyond closing. | Constraint enforced rather than hidden |

Asymmetry and history: A and B disagree about originals but agree about changeable replicas. C’s competence evidence concerns access, not aesthetics. D’s refusal of late closing is not evidence of hostility. Statements of shared purpose do not remove these distinct scopes.

System analysis: One approval label would let a provenance check be mistaken for an access check. Different criteria therefore need separate owners, and a change to the installation can invalidate one approval while leaving another intact. Decision power lies with D for hours, B for original handling, and A for artistic choices within those constraints; C’s access findings must be visible even without final decision power.

Specific interventions, ten:

| Intervention | Target and concrete act | Mechanism, cost, signal and prerequisite |
|---|---|---|
| I1 | A↔B: label original and replica before trial. | Separate preservation exposure; labeling cost; observable status; inventory accurate |
| I2 | B→A: log each reversible rearrangement once. | Traceability with creative freedom; record cost; applies to replicas only |
| I3 | C→A: attach access finding to the specific instruction version. | Narrow evidence; review cost; prevents stale approval; version visible |
| I4 | A→C: demonstrate text/audio alternative. | Capability evidence; design time; effect unknown until used |
| I5 | D→all: publish fixed room-close time before selection. | Transparent constraint; gives up late discretion; no trust feeling assumed |
| I6 | A→D: commit to reset task and duration estimate. | Trackable promise; cleanup cost; estimate unverified |
| I7 | D→C: reserve a test slot accessible to the review format. | Structural opportunity; venue cost; depends on availability |
| I8 | B→C: distinguish object history from visitor instructions. | No cross-domain authority inference; small annotation cost |
| I9 | A→B vulnerability: show a sample whose aesthetic choice may be vetoed for original safety. | A exposes preferred design to a bounded veto; meaningful only within agreed scope |
| I10 | All: use separate provenance, access, and timing acceptance fields. | Structural system change; coordination effort; narrower approvals survive unrelated changes |

Repair/design sequence: First classify objects and version the sample. Next test a reversible change, record provenance, and examine both instruction modalities. Before opening, inspect timing/reset; after each material version change, recheck only the affected approval. These are proposed trials, not a claim that the team has agreed. The checkpoints are proposed opportunities to observe commitments, not a forecast that a person’s trust will recover in a fixed number of days. Actual trust change would require observed recipient reliance, disclosures, or reports across later interactions; none exists in this constructed application.

Uncomfortable case contribution: A’s wish for creative latitude is compatible with B’s original-handling limit, but not with silently treating every review as aesthetic endorsement. D’s closing constraint may remain even if all share the exhibition’s purpose. This concerns the fictional party’s role, not a discovered trait of the real user. Confidence is moderate for the map’s logical fit to stipulated facts and low for any reaction prediction. Weakest assumption: how parties interpret the same event; their actual perspectives were not collected.

Source-claim boundary: this application does not assume that violations always outweigh trust-building, that erosion is always bidirectional, or that every integrity breach should be answered by over-delivery. The original research on response to alleged competence and integrity violations examined different conditions; it does not license false denial or a universal repair rule. [Kim, Ferrin, Cooper and Dirks, primary study](https://ink.library.smu.edu.sg/lkcsb_research/2368/)

Certificate: the dimensional assessment depends on event-specific evidence; a favorable event on competence does not supply an integrity commitment, and an unknown benevolence judgment is not a negative finding. The strongest alternative is that a hidden event changes the map, so the resulting allocation remains scoped to this case.

Subsequent application, executed: New generated acceptance record has three independent fields: provenance accepted for replica set v1; access instruction unresolved for audio draft v2; closing/reset plan accepted for the stated time. A single “team approves” badge is not used. No actual team has adopted the record.

Actual mind change: The trust design makes disagreement scopes inspectable while cooperation remains a proposed arrangement.

Benefit: The constructed artifact prevents one kind of approval from standing in for another; real coordination and trust effects remain unobserved.

Verdict: UNRESOLVED

Organization: The content preserves unknown dimensions and unilateral as well as reciprocal failure possibilities. The directional table retains risk and system exposure beside each assessment; intervention plans are distinct from observed outcomes.

Next attempts: Test a new event that changes one dimension only; obtain actual recipient perspective if a real case is supplied; compare a reliance decision before and after an intervention.
